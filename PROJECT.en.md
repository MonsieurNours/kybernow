# KyberNow — scope

English · [Français](PROJECT.md)

Ready-to-install Windows server (any graphics card: NVIDIA, AMD, Intel, eGPUs included; otherwise the processor) + web administration GUI, and native macOS, tvOS, iOS/iPadOS and Windows clients “in the style of Moonlight”, and a web client, built on [Kyber](https://kyber.tech) (low-latency streaming SDK by the VLC team, Rust + FFmpeg + VLC + QUIC). Three products under the KyberNow brand:

- **KyberNow Station**: the server installed on the Windows computer that streams its image (installer, services, notification area icon, updates);
- **KyberNow Admin**: the Station's administration in the browser (the `kyber-admin` service and its Svelte interface);
- **KyberNow Link**: the apps that show the image (Mac, Apple TV, iPhone and iPad, Windows) and the `/ecran` web client served by Admin.

## What Kyber provides (v0.29.0, 2026-10-09)

- Windows 10/11 server: Windows service (`kyservice` → `kycontroller`, `kyavserver`, `kynputserver`), notification area icon, NVENC recommended, single port `8080` TCP+UDP.
- Single config `kyber_config.toml` (encoder, minimum bitrate, port, TLS, JWT/OIDC, clipboard, gamepad, “Kidd” virtual displays). Most changes require a restart. Can be overridden with `KYBER_CONFIG`.
- Gamepads: ViGEmBus driver required on the server.
- Web client served by the controller at `/webclient/`.
- Client SDK: Rust core, C bindings (`libclient`, `libkynput`) through cbindgen; rendering through VLC (fork). `kyber-ios` app (iOS/tvOS) **not public**.
- No NAT traversal → LAN / VPN.
- Sources: https://gitlab.com/kyber (docs: `kyber/kyber`, apps: `kyber/apps/*`, core: `kyber/core/*`).

## Architecture

```

├── server/             # KyberNow Station
│   ├── admin/          # kyber-admin (KyberNow Admin): Windows service in Rust (axum)
│   ├── web/            # Admin's Svelte SPA and the /ecran web client, built and embedded in admin
│   ├── tray/           # notification area icon
│   ├── installer/      # installer (Rust + WebView2 + Svelte): Kyber + SudoVDA + ViGEmBus + kyber-admin + firewall + power
│   └── kyber-patches/  # patches to Kyber, overlay laid down by the installer
└── apps/               # KyberNow Link
    ├── core/           # Rust client core (kybernow-core): session, `console` (talking to Admin), inputs, sound, latency
    ├── apple/          # the core's C bridge for the Apple apps (libkybernow)
    ├── macos/          # macOS app (SwiftUI; KyberKit, shared with tvOS and iOS)
    ├── tvos/           # Apple TV app
    ├── ios/            # iPhone and iPad app
    ├── android/        # Android and Android TV app (Kotlin + Compose; the core's JNI bridge in android/jni)
```

### KyberNow Admin (kyber-admin, Windows)
- Runs as a Windows service, HTTPS on a dedicated port, access protected by a password.
- **Config**: reads/writes `kyber_config.toml` while keeping its comments (`toml_edit`), schema validation, applied with a controlled restart of the Kyber service.
- **Service**: start / stop / restart / state of the Kyber service.
- **Monitoring**: graphics card and driver (`Win32_VideoController`), load of the card and its encoder, streams in progress (Windows “GPU Engine” counters, for NVIDIA, AMD and Intel); in addition for NVIDIA, through NVML: NVENC sessions, frames per second, latency, power, temperature. Active session, live logs.
- **Pairing**: Admin's “Link devices” page: QR code and link `kybernow://adresse:port?name=…&fp=sha256:…` (address, Admin's port, fingerprint of its certificate; no secret). The app reads the QR code with the camera, or the pasted (or opened: `kybernow://` scheme) link. The fingerprint seen is compared with the one in the link or the announcement; with a plain address, the user compares it with Admin's (first 4 groups). Then the Admin account, verified and kept in the Keychain; certificate pinned. **With a code**: the device sends a 6-digit code to Admin without an account, which is accepted in Access › Devices or the icon's panel; it receives a Kyber account of its own (random password), accepted by Admin and Kyber, revocable in Devices (“Remove access”), with no change on the app side. See [server/README.en.md](server/README.en.md).
- **Discovery**: Bonjour/mDNS announcement `_kybernow._tcp` from Admin (TXT `v`, `name`, `fp`), UDP 5353 firewall rule for kyber-admin.
- **Apps' home screen**: `GET /api/stream/info` gives the computer's system (“Windows 11 Pro 24H2”, designed for a Station on other systems), `GET /api/stream/preview` a JPEG preview of the main display (GDI capture by the agent in the user's session, 10 s cache, never during a session), background of the home screen when the app has no image from the last session.
- **Profiles**: “Game” (low latency, gamepad, high fps) / “Desktop” (4:4:4, clipboard, multiple displays).
- **Web client** (`/ecran/`): served by Admin, with its session. Admin signs a JWT for Kyber (key set at installation), relays the HTTPS and WebSocket calls of the `kyclient_wasm` engine to kycontroller (which refuses other origins) and serves the engine's files from the installed `/webclient/`; the image arrives directly from Kyber over WebTransport. Details in [server/README.en.md](server/README.en.md). **Still to validate on the test computer**: the session end to end (image, sound, keyboard, mouse, gamepad, clipboard), takeover by another device, touch and the keyboard of phones and tablets (gestures are translated into mouse and keyboard events sent to the engine).

### Virtual display (stream session)
- **Start of session**: the client announces its resolution and refresh rate to kyber-admin (our apps), or we use the default mode; kyber-admin creates the SudoVDA virtual display at that mode, remembers the display layout, enables only the virtual display, and Kyber's capture follows it.
- **End of session**: virtual display removed, original layout restored.
- **Safety net**: the driver removes the display if it no longer receives a heartbeat (3 s); kyber-admin restores the layout when it starts and when no stream is being encoded any more (any graphics card); emergency keyboard shortcut.
- ✅ **Checked on 2026-10-19** on the test computer (RTX 3080 Ti, two 4K displays): 3840 × 2160 virtual display at 160 Hz created before connecting, physical displays turned off then restored, stream received at 152 fps, 8.3 ms median latency.
- **Pitfall**: Kyber's display enumerator sees the old layout for ~50 ms; `prepare` waits until Windows shows only the virtual display, then 1.5 s, before answering, and the apps' core waits for Kyber to announce the virtual display before choosing it.
- **Pitfall**: SudoVDA's watchdog (3 s) is armed as soon as the display is created. The heartbeat therefore starts from a dedicated thread as soon as `add` runs, not once the session is active: otherwise the display disappears during set-up (white screen on the client, encoder initialisation failure on the server).
- **Still to validate**: the “For any connection” mode (display created during the stream), and takeover by a 2nd device (disconnection of the 1st).
- **Architecture**: the service drives SudoVDA (IOCTL, heartbeat); a short-lived agent `kyber-admin display-agent`, launched with the SYSTEM token in the console session, changes the layout (CCD API).
- **Security trade-off**: SudoVDA is self-signed; its certificate is added to the computer's root authorities.

### Image quality: 4:4:4, HDR, VRR (Kyber 0.29)
- **4:4:4** ✅ checked on 2026-10-19 (HEVC, 3840 × 2160 at 160 Hz, client `--444`). Cost compared with 4:2:0: NVENC encoding ~9 ms median (p95 46 ms), decoding ~6.6 ms, total latency ~18 ms median. Offered in the “Desktop” profile (sharp text), not in the “Game” profile.
- **HDR** ❌ impossible with Kyber 0.29: capture (DXGI Desktop Duplication) is 8-bit BGRA. Keep Windows HDR turned off on the virtual display.
- **Multichannel and HD sound** (patch `server/kyber-patches/0001`): the txproto engine captures Windows output with all its channels; Kyber fixes the Opus bitrate at 128 kbit/s, and the patch makes it follow the number of channels. Setting `[kyavserver] audio_quality`: `standard` (128 kbit/s), `hd` (default: 256 kbit/s in stereo, 576 in 5.1, 768 in 7.1), `studio` (Opus maximum); `audio_bitrate` for an exact value. The libavconv engine also keeps 5.1 and 7.1 (0008); `audio_layout = "stereo"` prevents it, for the web client that only plays stereo. The app offers Auto, Stereo, 5.1, 7.1 or None; Auto follows the Mac's audio output.
- **VRR**: on the server, Kyber sends a frame when the screen changes (frame rate following the content). On the client, each frame goes to the display as soon as it is decoded, the most recent replacing the others: on a ProMotion / Adaptive-Sync display, the display follows the arrival of frames. Vertical sync can be turned off (minimal latency, possible tearing). No VRR on Apple TV.
- **Decoding by the app**: patch `apps/macos/kyber-patches/0001` on libkyclient (`kyclient_video_player_config_set_packet_sink`): video packets (Annex B, parameter sets, keyframe, pts) go to the app instead of VLC. KyberKit decodes them with VideoToolbox (hardware required, real-time mode, output in the Apple silicon lossless compressed formats, read without copying by Metal) and draws them with Metal (YCbCr → RGB conversion according to the stream's matrix). Measured offline on an M4 Max at 2560 × 1440 (2026-10-20): 2.0 ms decoding in 4:2:0, 2.7 ms in 4:4:4. The session does not use VLC: AV1 is only offered to Macs that decode it in hardware (M3 chips and later). Code without AppKit (decoder, renderer, capabilities, sound output): reused as is on iOS/tvOS.
- **Sound by the app**: the same patch passes Opus packets to the app (`kyclient_audio_session_config_set_packet_sink`). The core's sound engine decodes them (libopus multistream, loss concealment) into an adaptive buffer of about twenty ms (VLC: a fixed 50 ms, plus its own); Core Audio (Apple apps, 5 ms requests to the sound card) or WASAPI (Windows) pull the samples. On the server, `server/kyber-patches/0004`: 10 ms Opus packets in `lowdelay` (WASAPI capture itself stays at the Windows period). Sound and image each leave as soon as they are ready; the offset is shown in the session bar. Full list of changes: [docs/kyber-changes.en.md](docs/kyber-changes.en.md).
- **Mouse, clipboard, bitrate, latency**: Auto, Desktop or Game mouse (relative, GCMouse), set in the session bar and with ⌃⌥⌘M; Auto switches to game mode when Admin sees a full-screen game on the computer (not a browser or a video player), not merely when the pointer is hidden, which Windows does constantly with no mouse plugged in; text clipboard shared both ways (`apps/macos/kyber-patches/0002` on libkynput); profile bitrate proportional to the session's pixels per second; end-to-end latency (capture → display) measured with Kyber's timestamps and clock alignment, in the bar and on the home screen.
- **Recovery after a loss**: under progressive refresh, NVENC never sends a keyframe, and VideoToolbox freezes the image after a loss that FEC does not repair. The app therefore requests a keyframe (`POST /force_idr`, `server/kyber-patches/0005` on kycontroller, in the overlay), and restarts the stream if there is no answer within 1.5 s.
- **Resolution**: “Like this display” follows the Mac's display to the pixel (5K, 6K), up to 7680 × 4320 (limit of Admin and the virtual display), 4096 wide at most in H.264 (NVENC limit). “4K at most” option to lighten encoding, decoding and bitrate.
- **Client capabilities**: at launch, the app checks the hardware decoders (H.264, HEVC, AV1) and actually decodes an HEVC 4:4:4 frame, requiring hardware. The profiles are brought down to them (without hardware 4:4:4: 4:2:0 with more bitrate; without HEVC: H.264); the settings' “This Mac” card shows them, with the display's resolution and refresh rate (variable or not).

### Virtual audio output (stream session)
- **Why**: without it, sound also comes out of the computer's speakers, in the format set in Windows, and disappears if the output was the HDMI of a display turned off by the virtual display.
- **Driver**: Steam Streaming Speakers (Valve, signed by Microsoft, stereo to 7.1), installed by the installer from Steam's folder if present (as Sunshine and Apollo do). No open-source driver is signed (Virtual-Audio-Driver requires test mode); plan B: our own driver signed by Microsoft (EV certificate + Partner Center in the name of Les Lignes Claires).
- **Session**: `prepare` receives `audio_channels` (2, 6, 8; 0 = sound on the computer). Sound switches to the virtual speakers set to that format (`IPolicyConfig`, like the Sound panel) before the virtual display; at the end, the original output comes back after the displays (it can come back with them). Same safety nets as the virtual display (state on disk, 20 s without news). Admin's “Sound” page: trigger and number of channels.

### Mouse pointer
- **Finding**: Kyber does not draw the cursor into the image; the client draws it from the computer's announcements and switches to relative mouse as soon as Windows says it is hidden, with no delay. Hence a cursor that flickers or disappears.
- **Fixes**: txproto announces a hide only after 250 ms (`server/kyber-patches/0002`); Admin turns off “Hide pointer while typing” for the duration of the session; the apps keep the cursor visible with the Desktop mouse and reserve relative mouse for Game mode (see “Mouse” above).
- **Still possible**: Windows with no physical mouse hides its cursor permanently; to watch on a computer with no mouse.
