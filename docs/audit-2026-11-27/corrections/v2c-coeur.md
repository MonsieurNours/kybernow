## Laissé, et pourquoi

- **Textes de KyberKit encore en Swift** : les textes du prêt, de l'invitation et du certificat dans `ShareCore` et le repli « pas de partage » restent en Swift : ils ne sont pas encore dans le catalogue du cœur, et les y mettre demande leurs clés dans `docs/i18n.md` (hors de ma zone).
- **Écran « Envoyer le journal » de Linux** : ses textes restent dans l'interface de Linux (ceux du dépôt sont dans le cœur) ; LG a le sien. Les deux écrans ne se ressemblent pas assez pour une seule copie.
- **Dessin (`canvas`) de Linux et de LG** : pas partagé. Linux dessine avec Skia sur une fenêtre, LG sur une surface de NDL à 1920 × 1080 ; ce qui se ressemble (rectangles arrondis, texte) dépend chaque fois de la bibliothèque. Écrit dans le README de `kybernow-ui`.
- **En-tête du journal de Windows** : son fichier `kybernow-journal.txt` garde son en-tête (il part par la fenêtre « Partager » de Windows, pas par le relais).
- **Erreurs PlayStation** : les textes `Display` des erreurs du protocole restent en français dans le cœur : ils vont au journal, jamais à l'écran.
- **« Personnalisé » d'Android** : l'app dit « Personnalisé » dès qu'un format ou un débit est choisi à la main ; le plan du cœur, seulement si ce format diffère de celui du profil. Pour le relais, un HEVC choisi à la main sur un profil déjà en HEVC part donc comme le profil. Sans effet sur l'image ; à aligner quand les règles de « Personnalisé » des réglages seront écrites pour toutes les apps.
- **Faux cœur des essais JVM d'Android** : `FakeCore` réduit la mémoire des réglages synchronisés et le plan aux réponses que l'app attend (les essais JVM n'ont pas `libkybernow.so`) ; les règles elles-mêmes sont essayées en Rust (`memoire_des_reglages_synchronises`, `passer_en_hevc` et les essais du plan).
- **Essai instable du cœur** : `relay.rs`, essai à la ligne 964, échoue parfois quand le port qu'il ouvre est déjà pris (d'avant cette phase).
- **Stylet, limites** : iPadOS ne dit pas si un Apple Pencil est associé (l'iPad compte comme « avec stylet » dès que le Pencil a servi dans l'app) ; sur Windows, une tablette dont le pilote a « Windows Ink » décoché n'est pas vue comme un stylet (elle n'envoie que la souris : pas de ligne) ; Linux compte « avec stylet » dès qu'un stylet a servi depuis le lancement. Un choix reçu d'un autre appareil pendant une session s'applique tout de suite sur Linux et Android, à la session suivante sur Windows et Mac (la session garde sa copie des réglages, comme le mode immersif). L'aide de « Synchroniser les réglages des ordinateurs » ne cite pas le stylet (texte de link-ui, hors de ma zone). Android : en repli souris (Station d'avant, ou « Souris »), le bouton du stylet tenu donne maintenant un clic droit, comme la règle le dit.
- **Hors de ma zone, touché quand même** : `scripts/release-entrees.sh` et `apps/linux/scripts/sources.sh` comptent `apps/ui-common` dans les sources de Linux et de LG (sans quoi leurs empreintes de publication l'ignoreraient).

- **Linux et LG** : interfaces (`cargo test -p kybernow-linux -p kybernow-webos --no-default-features` : 166 et 100 essais) ; code de l'appareil de Linux par `apps/linux/scripts/verifier-mac.sh --essais`  : 41 essais passent, le 42e est du code natif (carte graphique), comme avant ; LG pour armv7 par `apps/webos/scripts/build.sh --check`  : vérifié, sans avertissement.
- **Apple** (avec `KYBERNOW_IGNORE_RUNNING=1`, l'app de l'auteur restée ouverte) : `vendor-kyber.sh`, `build-kyclient.sh`, `apps/apple/scripts/build-apple.sh`, `build-kyber-tvos.sh`, `build-apple-mobile.sh tvos` et `ios`, `apps/core/scripts/build-apple.sh` pour `aarch64-apple-ios` et `aarch64-apple-ios-sim` : tout passe ; `xcodebuild` Debug de l'app Mac, de l'Apple TV (simulateur) et de l'iPhone/iPad (simulateur) : BUILD SUCCEEDED ; essais du pont Apple : 19.
- **Android** : `apps/android/scripts/build-native.sh` (les trois cibles), `./gradlew assembleDebug testDebugUnitTest` : APK construit, 462 essais JVM dans 45 classes, aucun échec ; `strings.py --check` : 830 textes à jour.
- **Windows** : `link-check.sh` x64 et ARM64 ; `build.sh` x64 et ARM64 : construction complète réussie, archives produites, aucun avertissement de l'app (elle a trouvé deux erreurs de mes commits précédents, corrigées) ; `cargo test -p kybernow-windows --features kyber-pyrowave` sur le Mac : 111 essais (l'un attendait encore l'espace ordinaire de TRANS-32, corrigé) ; `npm run check` de l'interface : catalogues alignés, aucune erreur.

## Notes de version

**FR**
- Avec PyroWave, les images HDR gardent leurs informations de luminosité jusqu'à votre écran.
- En quittant PyroWave pour un autre format, un débit réglé à la main pour PyroWave revient à 80 Mbit/s, qui conviennent au HEVC.
- Sur Windows, barre fermée, une petite capsule « ● Caméra » rappelle que la caméra est envoyée, et une icône que le micro l'est.
- « Envoyer le journal » par QR code fonctionne de la même façon sur toutes les apps qui le proposent.
- Stylet : choisissez « Pression » pour dessiner avec la pression, ou « Souris » pour vous en servir comme d'une souris, sans Windows Ink : dans le menu Souris de la barre (ou sa tuile), dans les réglages de l'ordinateur, ou avec Ctrl+Alt+Maj+P (⌃⌥⌘P sur Mac et iPad). Le choix est retenu pour chaque ordinateur.
- Les messages en français ont la bonne espace avant les deux-points, points-virgules, points d'exclamation et d'interrogation.

**EN**
- With PyroWave, HDR pictures keep their brightness information all the way to your screen.
- When you leave PyroWave for another format, a bitrate set by hand for PyroWave goes back to 80 Mbit/s, which suits HEVC.
- On Windows, with the bar closed, a small “● Camera” capsule reminds you the camera is being sent, and an icon that the mic is.
- “Send the log” by QR code works the same way in every app that offers it.
- Pen: choose “Pressure” to draw with pressure, or “Mouse” to use it as a mouse, without Windows Ink: in the bar's Mouse menu (or its tile), in the computer's settings, or with Ctrl+Alt+Shift+P (⌃⌥⌘P on Mac and iPad). The choice is kept for each computer.
- French messages have the right space before colons, semicolons, exclamation and question marks.
