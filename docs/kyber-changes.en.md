# What KyberNow changes in Kyber

English · [Français](kyber-changes.md)

KyberNow is built on Kyber 0.29 (AGPL-3.0, sources in `third_party/kyber-desktop`). Kyber's code is never modified in place in this repository: each change is a patch stored here, applied by a script at build time. Everything else (virtual display, virtual audio output, cursor, accounts) goes through the KyberNow console and Kyber's configuration, without touching its code.

| Patch | Where | What it changes | Why |
|---|---|---|---|
| `server/kyber-patches/0001-kyavservice-son-hd.patch` | kyavservice (server) | Opus bitrate according to the number of channels, configurable: `[kyavserver] audio_quality` = `standard` (128 kbit/s, Kyber's fixed value), `hd` (default: 256 kbit/s in stereo, 96 kbit/s per channel beyond that), `studio` (510 kbit/s in stereo, 256 kbit/s per channel); `audio_bitrate` in bit/s takes precedence. The txproto engine keeps the layout of the captured output (stereo, 5.1, 7.1). | 128 kbit/s for everything, even in 7.1: poor sound. |
| `server/kyber-patches/0002-txproto-curseur-stable.patch` | txproto `dxgi_cursor.c` (server) | A pointer hide is only sent after 250 ms without the pointer coming back; an unusable shape is ignored without changing the position or the visibility. | Windows hides the pointer for a few frames at the slightest keystroke or shape change: on the client, the pointer flickered and switched to relative mouse. |
| `server/kyber-patches/0003-txproto-son-continu.patch` | txproto `iosys_wasapi.c` (server) | Sound timestamps follow the samples, realigned on the WASAPI capture clock (QPC) if they drift from it by more than 40 ms or at each discontinuity. Packets marked silent are filled with zeros. | Packets read in bursts shared almost the same timestamp (“Queue input is backward in time”): choppy, distorted sound. Windows does not define the content of a silent packet. |
| `server/kyber-patches/0004-txproto-son-basse-latence.patch` | kyavservice `txproto/audio.rs` (server) | WASAPI capture and Opus packets of 10 ms instead of 20, Opus in `lowdelay` mode (CELT only, without SILK's look-ahead). | About 15 ms less latency on the sound. At the bitrates of 0001, the quality does not change to the ear. |
| `server/kyber-patches/0006-txproto-pointeur-deplacements.patch` | txproto `dxgi_cursor.c` (server) | Pointer movements are sent too (position only, empty bitmap, at most 60 per second) when it is visible. Kyber's input server then sends back the last known shape with the new position. | Kyber only sent the position when the pointer appeared, disappeared or changed shape. In game mode (relative mouse), the Mac's pointer is hidden and the image does not contain the Windows one: in a game's menus, no pointer could be seen at all. The app now draws it in the right place. |
| `server/kyber-patches/0005-kycontroller-image-cle.patch` | kycontroller (server) | New route `POST /force_idr`: forces a keyframe (IDR) on the video streams of the session that requests it, through the same mechanism Kyber uses when one of its relays falls behind. Same authentication and same scope as `/set_bitrate`. | With the encoder's progressive refresh (Kyber's default setting), NVENC never sends a keyframe by itself. When packets are lost beyond what error correction can repair, VLC carries on with a damaged image that repairs itself little by little; VideoToolbox, however, refuses all following frames and the image stays frozen. So the client requests a keyframe. |
| `server/kyber-patches/0007-kynet-envoi-image.patch` | kynet `driver/common.rs` (server) | 8 MB QUIC datagram queues for sending and receiving (1 MB by default), 8 MB UDP socket send and receive buffers. | Video goes out as datagrams, and quinn drops the oldest ones once its queue is full. A large 4K frame or a keyframe filled it while pacing spread it out: pieces of frames were lost on the computer itself, then the keyframe requested again filled it once more. The Mac no longer lost anything on its side since 0003. |
| `apps/macos/kyber-patches/0002-kynput-presse-papiers.patch` | libkynput (client) | C functions for the clipboard: `kynput_clipboard_text_{change,request,unavailable,data}_to_packet`, `kynput_clipboard_event_from_packet`, `kynput_clipboard_text_from_packet` (text, 60 KB at most, UTF-8 cut cleanly). | Kyber only has a clipboard handler for Windows, Linux and the web, and its C API can neither read nor build these packets. The macOS app makes the link with NSPasteboard; the iOS app will do it with UIPasteboard. |
| `apps/macos/kyber-patches/0001-kyclient-paquets-audio-video.patch` | libkyclient (client) | `kyclient_video_player_config_set_packet_sink` and `kyclient_audio_session_config_set_packet_sink`: packets (`kyclient_MediaPacket`: type, codec, config, keyframe, pts, lost samples, data) go to a callback in the app instead of VLC. Without a callback, nothing changes. New module `media_sink.rs`, forwarding task in `kymux_backend/desktop.rs`. Also `kyclient_client_request_keyframe`: `POST /force_idr` to the controller (server with 0005), with no effect on a server that does not know it (refusal logged). Watch out: `kyclient_video_session_config_default` copies the player's configuration, so the video callback must be set before it (otherwise the image goes to VLC). | The app decodes by itself (VideoToolbox + Metal, Opus + Core Audio): decoding in 1 to 3 ms, most recent frame always shown, variable refresh rate displays followed, sound with about twenty milliseconds of buffer instead of a fixed 50 ms, without depending on VLC (on iOS and tvOS too). |
| `apps/macos/kyber-patches/0003-kynet-tampon-de-reception.patch` | kynet `driver/quinn.rs` (client) | The QUIC client's UDP socket is created by KyberNow (socket2) with an 8 MB receive buffer (6, 4 or 2 MB if the system refuses), instead of macOS's 768 KB default. QUIC's queue of received datagrams also goes to 8 MB. | A 4K frame arrives as one burst, faster than the socket is read: the default buffer overflowed and the Mac dropped bursts of 20 to 30 packets in games ("dropped due to full socket buffers"), so keyframes had to be requested again. |

## Applying and rebuilding

- **Server**: `server/kyber-patches/build.sh` puts the files concerned back in their original state (git), applies all the patches in order (`*-kycontroller-*` in `kysdk/kyctl`, `*-kynet-*` in `kysdk/kymux`, the others in `kysdk/kymedia`), rebuilds kyavserver and txproto for Windows from macOS (MinGW, UCRT), then kycontroller (Rust, same options as the official release: `auth-jwt,auth-oidc,cli,kyhub,win32-hide-console,win32-tray`). Finally it assembles `third_party/payload/kyber-overlay/`. The installer and `update.ps1` lay this overlay down on top of Kyber 0.29's files; the previous version is kept in `kyber\avant-maj`. Details of the cross-compilation: [build-notes.en.md](build-notes.en.md).
- **macOS client**: `apps/macos/scripts/build-kyclient.sh` applies each patch to the repository named by its file (`*-kyclient-*`: `kysdk/kyctl`, `*-kynput-*`: `kysdk/kynput`, `*-kynet-*`: `kysdk/kymux`), rebuilds libkynput and libkyclient (`cargo cinstall`) and replaces them in `apps/macos/Vendor/`.
- **Apple TV client**: `apps/tvos/scripts/build-kyber-tvos.sh` applies the same patches, builds libkynput (without SDL: gamepads go through GameController), libkyclient and libopus as static libraries for Apple TV and its simulator (Rust nightly, `-Zbuild-std`), adds empty functions for the libvlc calls (never reached: image and sound go to the app) and puts everything into `apps/tvos/Vendor/KyberSDK.xcframework`.

Adding a patch: change the sources in `third_party/kyber-desktop`, then save the difference here. For the server, a `NNNN-sujet.patch` file in `diff -u` format (paths `a/…` and `b/…` relative to `kysdk/kymedia`). For the client, `git -C kysdk/kyctl diff -- kyclient` or `git -C kysdk/kynput diff -- kynput`, in a file named after the repository (`NNNN-kyclient-…`, `NNNN-kynput-…`). Then complete the table above, in both languages.

## Handled without changing Kyber's code

- **Configuration** (`kyber_config.toml`, through the console): port, encoder, single Basic account, JWT secret drawn at random at installation (instead of the development key shipped with Kyber), console settings (Settings and Advanced pages), comments kept and a backup at each write.
- **Virtual display**: SudoVDA (Apollo 0.4.6's driver), created by the console for each session at the size of the client's display. The layout is saved by Windows (`SDC_SAVE_TO_DATABASE`, `CDS_UPDATEREGISTRY`) so that it does not reapply it in a loop. Removed at the end of the session, original displays restored.
- **Sound**: default output switched to Steam's virtual speakers (Steam Streaming Speakers) with the right number of channels during the session, then put back as before. Sound therefore no longer comes out of the computer's speakers.
- **Pointer**: “Hide pointer while typing” turned off for the duration of the session, then turned back on.
- **Capture engine**: KyberNow assumes Kyber's historical engine (`[kyavserver] backend = "txproto"`, the default). The new engine (`libavconv`) does not see the SudoVDA virtual display, numbers the displays 0, 1… and does not have patches 0002, 0003, 0004 and 0006: the console says so next to the setting.

## To report to the Kyber team

Server patches 0001 to 0007 fix general defects or limits: fixed Opus bitrate, cursor flicker, WASAPI timestamps, sound latency, no keyframe on request from a client that lost packets, pointer position missing while it moves. They could be proposed as they are. The client patches are API extensions, with no effect if the app does not use them.
