# Audit of 27 November 2026

*[Français](audit-2026-11-27.md)*

A full audit of the repository after 0.11.7, ahead of the release: bugs, security, optimisations, factoring, dead code and docs. Twelve sessions ran it in parallel, one per area, each with its own sub-agents, read-only (nothing built, nothing tried on a device). Every finding was re-read in the code before being kept; the most serious ones were checked a second time during consolidation. The detailed reports, in French, are in [`audit-2026-11-27/`](audit-2026-11-27/).

## The 27 critical findings

All are verified in the code, except two plausible ones (AND-04, MAC-01). The six marked ✔︎ were re-read a second time during consolidation.

| | Finding | What happens |
|---|---|---|
| ✔︎ | **TRANS-01** release | **The published 0.11.7 does not contain the fix it announces**: `kybernow-micro.exe` and `kybernow-camera.exe` in `kybernow-update.zip` are still console programs (PE subsystem 3, checked on the published files). The Windows overlay fingerprint ignores `server/micro`, `server/camera` and `server/encoder-check`, so the step was "reused" with the old binaries. |
| ✔︎ | **REL-01** relay | A computer or team name goes unescaped into `<title>`: a `meta refresh` sends members to a phishing site from share.kybernow.app (the CSP blocks scripts, not that). |
| ✔︎ | **STLIN-01** (= STWIN-09) Linux Station | The root update service follows a link swapped in after its check: a local account makes it copy `/etc/shadow` as 0644. With STLIN-02 (0666 socket), any local account drives this service. |
| ✔︎ | **WINAPP-02** Windows installer | `cmd /C start "" url`: a `&` in an address coming from a relay page runs a command. |
| | **KYB-01** Kyber patches | PyroWave writes past its output buffer (Windows and Linux Stations). |
| | **STWIN-01, 02, 03** Windows Station | Power loss during the update swap: Station without Kyber and without rollback; micro/camera helpers never stopped (swap and installer fail, services already removed); `kyber-admin` has no automatic restart. |
| | **STMAC-01** Mac Station | `kybernow-display lock` does not lock: after Admin restarts mid-loan, the session stays open. |
| ✔︎ | **COEUR-02** core | Wrong clock on 32-bit (webOS armv7, Android armeabi-v7a): `timespec` declared as `i64`. Latency, loss and statistics are wrong on LG TVs. |
| ✔︎ | **COEUR-04** core | After a Station restart, `renew` recreates micro and camera: the app talks to orphaned objects. |

| | **IOS-01** iPhone/iPad | Every session stays in memory (cycle through the keyboard row) until the app is evicted. |
| | **MAC-01, 02, 03** Mac | Rust can call back into a freed Swift object; PyroWave never commits its command buffer (permanent freeze); the Vendor fingerprint ignores the Station patches (release with stale libraries). |
| | **WINAPP-01** Windows app | GPU lost: the picture freezes with no recovery. |
| | **AND-01, 02, 04, 05, 09** Android | No panic hook and no exportable log; null PyroWave swapchain after a failed recreation; `surfaceDestroyed` returns while the decoder still writes; focus loss not handled (desktop mode); use-after-free in "Receive from another device". |

## Security, beyond the critical ones

**Relay (22).**
- Unbounded delegated rights and merged expiries (REL-02, 03).
- Rights kept after leaving a team (REL-04).
- An unverified account a third party can take over (REL-05).
- Passkey and two-factor added without the password, and two-factor that fails open if the secret no longer decrypts (REL-06, 07).
- Sign-in that can be blocked from outside (REL-08).
- No PKCE (REL-09).
- Admin token sent over `http` (REL-10).
- Unlimited invitations (REL-13).
- Unbounded memory and timeouts on QUIC, TCP and HTTP (REL-14 to 19).
- Unsigned `:latest` image updated nightly (REL-20).
- No HSTS (REL-21).
- Unsalted recovery codes (REL-22).

**Windows Station (15).**
- `device_id` trusted without checking the account, so one device can act on another's session (STWIN-04).
- A standard Windows account can bind the Station (STWIN-05).
- 6-digit lend and share codes rate-limited per exact address only (STWIN-06).
- Recycled pid killed by SYSTEM (STWIN-07).
- Lend rules that can be bypassed (STWIN-08).
- Brute force of Kyber accounts from the local network (STWIN-10).
- Installer tools run by bare name (STWIN-11).
- Camera image readable by everyone (STWIN-12).
- Host tokens readable by the friend during a loan (STWIN-14).
- Junction in the recording folder (STWIN-15).

**Mac and Linux Stations (10).**
- Secrets in 0644 outside Windows (STCOM-02).
- Any app can push frames into "KyberNow Camera" (STMAC-03).
- `audio-input` entitlement given to all ten executables (STMAC-04).
- Loan accepted without unlocking (STMAC-05).
- Wrong screen captured for a guest (STLIN-06).

**Kyber patches (6).**
- One uplink packet makes the Station allocate 4 GiB (KYB-02).
- A guest acts on every host screen (KYB-03) and forces keyframes (KYB-04).
- Unlimited virtual gamepads (KYB-28).
- Unlimited loss reports (KYB-35).
- kynput panics on a short packet, even from a spectator (KYB-38).

**Elsewhere.**
- With no known fingerprint, the core accepts any certificate (COEUR-19).
- 6-digit PlayStation code with no attempt limit (COEUR-20).
- 12-hour token and friend password in clear in the web client (WEB-14, 15).

## What keeps coming back

1. **A panic takes down the app or the service, without a trace.**
   - No `extern "C"` function in the bridges catches panics (COEUR-07 to 09).
   - Android has no hook to logcat (AND-01).
   - `kyber-admin` does not restart (STWIN-03).
   - Shared remedy: `catch_unwind` in the bridges, a panic hook to each platform's log, and service restart.
2. **Settings files get lost or corrupted.** WEBOS-01 and its Linux twin, WINAPP-04, 05 and 57, STWIN-31, MAC-14. Shared remedy: atomic write under a lock, and never rewrite an unreadable file (set it aside).
3. **Nothing restarts after losing the GPU or decoder.** WINAPP-01, WEB-01 and 02, MAC-02, AND-02 and 03, LINAPP-13 to 16. Each app has its own recovery, often incomplete.
4. **The lifecycle leaves inputs stuck.** Focus lost, sleep, background: modifiers, sticks, drags and Pencil stay pressed (AND-05, IOS-04 to 06, MAC-06, 09 and 10, COEUR-10 and 11, TVOS-01).
5. **The Stations' local services trust too much.** Sockets and files too open, `device_id` not tied to the account, symlinks followed (STLIN-01 to 03, STWIN-04 and 05, STCOM-02, STWIN-12, STMAC-03).
6. **Updates are not safe everywhere.** Windows swap with no recovery (STWIN-01, 02, 23 to 28); Link OS never working (LINAPP-01 to 03, 07, 08); unsigned relay image (REL-20).
7. **Session logic is rewritten in every app instead of living in the core.**
   - Already diverging: HDR, PyroWave header, picture stream, session plan, mDNS, PlayStation packet (WINAPP-49 to 54), synced settings (LINAPP-40), the iOS and tvOS session (IOS-21).
   - On the Kyber side, copies of `kn_timing.h`, `kn_hdr_*.h` and the shared PyroWave code have produced two bugs (KYB-44 and 45, STCOM-11).
8. **Release fingerprints miss inputs.** TRANS-01 (micro and camera in 0.11.7), TRANS-02 (Linux Station), TRANS-03 (Mac PyroWave), TRANS-04 (nightly), TRANS-16, MAC-03 (Mac Vendor): a "reused" step can ship a stale binary. Shared remedy: one input function per product, tested, plus a check on the output (PE subsystem, versions).
9. **Some tests protect nothing.** Core tests are not in CI (COEUR-49), nor is the relay (TRANS-12), and some Mac tests cannot fail (MAC-39).

## Proposed fixes

**Right away: TRANS-01 and a 0.11.8.** Complete the overlay fingerprint, check the helpers' PE subsystem before publishing, rebuild and publish.

**Wave 1: critical and security findings, plus the small bugs in the same files.** One session per area, each in its own worktree. None touches another's files, and each is merged into `main` at the end. Its unit tests pass, but nothing is tried on a device.

**Wave 2: factoring, dead code, docs and translations**, once wave 1 is merged, because it cuts across the apps:
- move what diverges into the core (point 7 above, TRANS-34 to 36 and 40 to 42);
- a shared iOS/tvOS session file;
- shared Kyber headers;
- translation catalogs (TRANS-25, 26, 29 to 33);
- gaps with `link-ui.md`;
- FR/EN doc pairs, `ROADMAP` and site (TRANS-43 to 47);
- 179 MB of site video tracked by git (TRANS-48).

**Build constraint.** The core and the apps build from the release trees (`third_party/arbres`), which are shared. Several sessions compiling at once each need their own tree, or must take turns; this has to be settled before launching wave 1.

## What is sound

Each report ends with its own list. In short:

**Core.**
- No other deadlock like the one fixed in 0.11.7: no call to the app or to Kyber under a core lock.
- Correct audio ring buffer.
- Bounded PlayStation network reads.
- Updates verified by signature before anything is read.
- No TODOs, and all 22 dependencies are used.

**Relay.**
- `__Host-` cookies and signed CSRF.
- 256-bit tokens compared in constant time.
- Argon2id.
- Anti-replay TOTP.
- Complete WebAuthn.
- Strict CSP.

**Kyber patches.**
- Every new field is optional on both sides, so an older app or Station keeps working.
- Fixed-algorithm JWT with mandatory `aud`.
- No lock held across an `await`.

**Windows Station.**
- What the 20/10 audit raised is fixed (ACL, JWT key).
- Signed update, re-checked by the applier.
- Shared memory of the camera and micro protected against frame injection.
