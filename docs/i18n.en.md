# KyberNow's languages

English · [Français](i18n.md)

Every installer, KyberNow Admin, the tray icon and the KyberNow Link apps exist in French and English. Decided on 21/10/2026: automatic detection, manual choice possible, texts in per-language catalogues so that another language can be added without going through everything again (except Linux and LG TVs, see “Files”).

## Rule

- **System language** (Windows: the user's display language, `GetUserPreferredUILanguages`; Mac, Apple TV, iPhone and iPad: the system's preferred languages; Android: Android's language; Linux, Steam Deck, Raspberry Pi and LG TVs: the first preferred language given by SDL, `SDL_GetPreferredLocales`, and on Linux `LANG` as a fallback; browser: `navigator.languages`): if the first one starts with `fr`, French; **any other language, English**.
- **Manual choice** in each app's settings and in Admin: “Auto” (default), “Français”, “English”. It applies to this app on this device only (the app's settings file; the browser's `localStorage` for Admin and the web client; the app's `AppleLanguages` on Mac, Apple TV, iPhone and iPad, which needs a relaunch; Android's per-app language, `AppCompatDelegate`, also settable in Android's settings from Android 13). KyberNow Link OS asks for the language on first boot.
- The **installers** have no setting: Windows' language. Nor does the **tray icon**.
- **Logs** (`*.log`, macOS's log) stay in French: they are for diagnosis, not part of the interface.

## Files

- **Web interfaces** (Svelte: Admin and the `/ecran` web client in `server/web`, the installers of the Station `server/installer/ui` and of the Windows app `apps/windows/setup/ui`, the Windows app `apps/windows/ui`): `src/lib/i18n/fr.json` and `en.json` (same keys, nested objects per screen), a `t('screen.key', { name })` function that replaces `{name}`, and a reactive language state. French is the source; a key missing in English falls back to French (and shows up in `npm run check`, where a script compares the keys of both files).
- **Rust** (messages of Admin `server/admin/src/i18n/`, the tray icon `server/tray/i18n/`, the installers `server/installer/i18n/` and `apps/windows/setup/src/i18n/`, the Windows app `apps/windows/src/i18n/`, the core `apps/core/src/i18n/`): embedded `fr.json` and `en.json` catalogues (`include_str!`) and a `tr(lang, "key", &[("name", …)])` function. Same fallback rule. Admin's settings texts are in French in `schema.rs` and in English in `server/admin/src/i18n/schema.en.json`. The tray panel (`server/tray/src/panel.html`) receives the `panel` part of the tray's catalogue.
- **Mac, Apple TV, iPhone and iPad**: Xcode string catalogues (`Localizable.xcstrings` in `apps/macos/KyberNow`, `apps/macos/KyberKit`, `apps/tvos/KyberNowTV`, `apps/tvos/TopShelf`, `apps/ios/KyberNowIOS`), French as the source language, English translation; `developmentLanguage: en` in `project.yml` (hence `CFBundleDevelopmentRegion` set to `en`) so that any untranslated language falls back to English. Deliberate exception to the rule: these apps go through the whole list of preferred languages (German then French gives French). `apps/macos/scripts/check-strings.py --fix` gives new texts their explicit French value (without it, Xcode does not write the French file): run it again after any addition.
- **Android**: `apps/android/scripts/strings.py` holds each text on one line (key, French, English) and writes `res/values/strings.xml` (English, the fallback for any other language) and `res/values-fr/strings.xml`, French typography included. Edit the script, not the files it produces.
- **Linux (Raspberry Pi and KyberNow Link OS included) and LG TVs**: no catalogue, both texts are written in place, `tr("…", "…")` (`apps/linux/src/i18n.rs`, `apps/webos/src/i18n.rs`); `decimal()` writes the decimal comma in French. The core gets the same language (`kybernow_core::i18n::set_current`).
- A new language: one more file per catalogue (`de.json`, language added to the Xcode catalogue, `values-de` written by `strings.py`), a third text in `tr` for Linux and LG TVs, and its line in the rule above.

## What the Station tells devices

- The apps (through the Rust core: every KyberNow Link app) and the web client send `Accept-Language` with the chosen language (`fr` or `en`) on every request to Admin; Admin answers in that language (error messages, `verify_error`, refusal reasons, texts meant for the user). Without the header (apps older than 0.3.0): French.
- Admin itself follows the browser (and its manual choice); the tray icon follows Windows' language.
- Admin's **event feed** keeps the event's type and parameters (`key`, `params`; `kind` stays the level, `info` or `warn`) and the sentence is written when read (`GET /api/events`), in the viewer's language. An event recorded before 0.3.0 keeps its French text.

## Release notes

- `CHANGELOG.md` (French) and `CHANGELOG.en.md` (English) remain the source.
- The GitHub release carries both: the French section, then a `<!-- en -->` line, then the English section. Admin (Updates page) and the apps that update through the Rust core (Windows, Android, LG TVs, Linux) take the part in their language (the whole text if there is no marker: releases before 0.3.0, in French).
- The Mac app's Sparkle feed: English as the default description (any language other than French), French as a per-language link (`xml:lang="fr"`) to `site/updates/notes/X.Y.Z/KyberNow-Link-macOS.fr.html`.

First mention in a screen or a page: “KyberNow Station”, “KyberNow Admin”, “KyberNow Link”; then “the Station”, “Admin”, “the app”. Kyber (the streaming engine, `kyber` service) stays Kyber, not the Station. In English, “link” also means the `kybernow://` link: prefer “pairing link”, “connection quality” where a text would become ambiguous. Technical identifiers do not change (`kyber-admin`, `console` in the code, `kybernow://`, `KyberNow` folders).

Typography: in French, narrow no-break space before “: ; ! ?” and « » quotes; in English, no space before punctuation, “ ” quotes, capital letter only at the start of labels (“Connect”, “Keep the last image”). The tone stays the same: short, direct, formal “vous” on the French side.

## Documentation

- Every document exists in French (`*.md`, the source) and in English (`*.en.md`, next to it, same structure). A change updates both in the same commit. The glossary and typography above apply to the documentation too.
- A document describes the project as it is: what exists, how it works, how to use it. No narrative (“from now on”, “no longer”, “since milestone 4”, “replaces the old…”): history lives in `CHANGELOG.md` and in git.
- What stays, in the present tense and with its reason: compatibility with what people have installed (“the Windows app 0.3.1 and earlier looks for `KyberNow-Client-Setup.exe`: that name is published as a copy until those versions are gone”) and pitfalls (what not to do, and why). A version is only quoted when it helps understanding.
- A decision (table in `PROJECT.md`): the one in force and its reason, with a date as a marker if useful. An abandoned decision goes, or into a short “Set aside” section if that saves reopening the debate.
- Dated records (audit, proposals, prototype and its results, measurements) are archives, in `docs/archives/`: they keep their date and context (hardware, version), and are not rewritten. A living document that relies on them states the fact that is still true, and only links to the archive as its source.
- What is planned (upcoming features, work in progress, decisions to make) lives in [`ROADMAP.en.md`](../ROADMAP.en.md) (French: `ROADMAP.md`), at the root, and nowhere else. A current limitation is written in the present tense, without a promise (“no QR code with the camera”).
- Code comments follow the same rules: they say what the code does and why, keep the pitfalls, and tell neither history nor plans.
- Exceptions to the two-language rule: `server/kyber-patches/upstream/README.md`, a letter to the Kyber team, in English only; `apps/linux/flatpak/LICENSES.md`, installed as is in the packages; the audit and proposals archives, in French only.
