# KyberNow's languages

English · [Français](i18n.md)

Every installer, KyberNow Admin, the tray icon and the KyberNow Link apps exist in French and English. Decided on 21/10/2026: automatic detection, manual choice possible, texts in per-language files so that another language can be added without going through everything again.

## Rule

- **System language** (Windows: the user's display language, `GetUserPreferredUILanguages`; Mac, Apple TV, iPhone and iPad: the system's preferred languages; browser: `navigator.languages`): if the first one starts with `fr`, French; **any other language, English**.
- **Manual choice** in each app's settings and in Admin: “Auto” (default), “Français”, “English”. It applies to this app on this device only (the app's settings file, the browser's `localStorage` for Admin and the web client, the app's `AppleLanguages` on Mac, Apple TV, iPhone and iPad, which needs a relaunch).
- The **installers** have no setting: Windows' language.
- **Logs** (`*.log`, macOS's log) stay in French: they are for diagnosis, not part of the interface.

## Files

- **Web interfaces** (Svelte: Admin, `/ecran` web client, installers, Windows app, tray panel): `src/lib/i18n/fr.json` and `en.json` (same keys, nested objects per screen), a `t('screen.key', { name })` function that replaces `{name}`, and a reactive language state. French is the source; a key missing in English falls back to French (and shows up in `npm run check` through a test that compares the keys).
- **Rust** (messages of Admin, the installers, the Windows app, the core): embedded `fr.json` and `en.json` catalogues (`include_str!`) and a `tr(lang, "key", &[("name", …)])` function. Same fallback rule.
- **Mac, Apple TV, iPhone and iPad**: Xcode string catalogue (`Localizable.xcstrings`), French as the source language, English translation; `developmentLanguage: en` in `project.yml` (hence `CFBundleDevelopmentRegion` set to `en`) so that any untranslated language falls back to English. Deliberate exception to the rule: macOS and tvOS go through the whole list of preferred languages (German then French gives French). `apps/macos/scripts/check-strings.py --fix` gives new texts their explicit French value (without it, Xcode does not write the French file): run it again after any addition.
- A new language: one more file per catalogue (`de.json`, language added to the Xcode catalogue) and its line in the rule above.

## What the Station tells devices

- The apps (through the Rust core: Windows, Mac, Apple TV, iPhone and iPad) and the web client send `Accept-Language` with the chosen language (`fr` or `en`) on every request to Admin; Admin answers in that language (error messages, `verify_error`, refusal reasons, texts meant for the user). Without the header (apps older than 0.3.0): French.
- Admin itself follows the browser (and its manual choice); the tray icon follows Windows' language.
- Admin's **event feed** keeps the event's type and parameters (`key`, `params`; `kind` stays the level, `info` or `warn`) and the sentence is written when read (`GET /api/events`), in the viewer's language. An event recorded before 0.3.0 keeps its French text.

## Release notes

- `CHANGELOG.md` (French) and `CHANGELOG.en.md` (English) remain the source.
- The GitHub release carries both: the French section, then a `<!-- en -->` line, then the English section. Admin (Updates page) and the Windows app take the part in their language (the whole text if there is no marker: releases before 0.3.0, in French).
- The Mac app's Sparkle feed: English as the default description (any language other than French), French as a per-language link (`xml:lang="fr"`) to `site/updates/notes/X.Y.Z/KyberNow-Link-macOS.fr.html`.

## Glossary

The terms already used in the English documents (`*.en.md`) and on `site/en/` are authoritative. Main ones: see the table in [i18n.md](i18n.md#glossaire) (French → English). Product names: **KyberNow Station** then “the Station” (the server; not “KyberNow Server” or “the shared computer”), **KyberNow Admin** then “Admin”, no article (not “the console”), **KyberNow Link** (the apps and the web client; not “the KyberNow app” or “KyberNow Client”). “Computer” stays for the machine itself (“a computer running KyberNow Station”); Kyber (the streaming engine, `kyber` service) stays Kyber. “Link” also means the `kybernow://` link: prefer “pairing link”, “connection quality” where a text would become ambiguous. Technical identifiers do not change (`kyber-admin`, `console` in the code, `kybernow://`, `KyberNow` folders).

Typography: in French, narrow no-break space before “: ; ! ?” and « » quotes; in English, no space before punctuation, “ ” quotes, capital letter only at the start of labels (“Connect”, “Keep the last image”). The tone stays the same: short, direct, formal “vous” on the French side.

## Documentation

- Every document exists in French (`*.md`, the source) and in English (`*.en.md`, next to it, same structure). A change updates both in the same commit. The glossary and typography above apply to the documentation too.
- A document describes the project as it is: what exists, how it works, how to use it. No narrative (“from now on”, “no longer”, “since milestone 4”, “replaces the old…”): history lives in `CHANGELOG.md` and in git.
- What stays, in the present tense and with its reason: compatibility with what people have installed (“the Windows app 0.3.1 and earlier looks for `KyberNow-Client-Setup.exe`: that name is published as a copy until those versions are gone”) and pitfalls (what not to do, and why). A version is only quoted when it helps understanding.
- A decision (table in `PROJECT.md`): the one in force and its reason, with a date as a marker if useful. An abandoned decision goes, or into a short “Set aside” section if that saves reopening the debate.
- Dated records (audit, prototype results, measurements) are archives: they keep their date and context (hardware, version), and are not rewritten.
