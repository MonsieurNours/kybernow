# The Rust core in the Apple apps

English · [Français](coeur-apple.md)

The Mac, Apple TV, iPhone and iPad apps rest on the Rust client core (`apps/core`, crate `kybernow-core`), the one every KyberNow Link app uses ([apps/core/README.en.md](../apps/core/README.en.md)). Everything that does not depend on display lives there: the session (talking to Admin, Kyber, reconnection, keyframe, display, latency, profiles), the inputs and the sound. Decoding (VideoToolbox), rendering (Metal), the views and the system APIs stay in Swift. One code for every app.

## What goes where

```
Swift (KyberKit, apps)                      Rust (kybernow-core, through kybernow-apple)
──────────────────────                      ──────────────────────────────────────────
VideoPipeline, VideoDecoder, VideoRenderer  session: preparation, connection, display
(VideoToolbox, Metal), AV1                  choice, starting and relaunching the picture,
AudioPlayerCore: Core Audio output          reconnection, virtual display requested again,
InputCore: event capture into the           keyframe (300 ms, 1.5 s), fallback without a
core's input chain                          picture (bitrate, 4:2:0), size of the
StreamView, MetalSurface, Passage,          computer's display, mode policy (“Restore”),
SessionChrome, SessionStats, HomeView…      adapting to the device's screen, heartbeat, end
SessionController: the window, the bar,     console: info, preview, pairing, fingerprint
the capsules, full screen, the Mac's        latency: path of a frame, losses, holes,
screen, the Keychain, the last image        rejected measurements, session median and p95
SessionEngine, ConsoleClientCore,           inputs: retry queue, keyboard, gamepads,
CoreBridge, LatencyReporting: the core      pointer, release all, clipboard
as seen from Swift                          sound: Opus, adaptive buffer, drift, downmix
                                            profiles and bitrate, language, updates
```

The core knows nothing of display: the platform hands it a `Platform` (window, where to send picture and sound packets, the kynput input chain, state callbacks). On the Mac, Apple TV, iPhone and iPad, `SessionEngine.swift` (shared KyberKit) provides it, through the C API.

The Windows app uses the same session, the same input module and the same sound engine; its clipboard stays kynput's. What the session does for the Apple apps (path of a frame and losses in the latency, keyframe request repeated every 300 ms then the stream relaunched at 1.5 s, fallback when no picture comes within 4 s — bitrate brought down to 250 Mbit/s, then 4:2:0, for this session only —, tracking of the computer's display size, mode policy with “Restore”, adapting to a new mode of the device's screen, choosing a display from the bar, bitrate cap, end report) can be switched off or has no effect for Windows, which keeps its own keyframe and first-picture watches. The Android, Linux and webOS apps use the core's watches, like the Apple apps. The connection's last resort (restarting the Station, below) applies to all of them, Windows included.

## Each app

KyberKit is a single module, built by all three Xcode projects, core included: `SessionEngine`, `ConsoleClientCore`, `CoreBridge`, `InputCore`, `AudioPlayerCore` and `LatencyReporting` serve everywhere. Each platform keeps only its session view, its Metal surface and the capture of its events.

- **Mac** (`apps/macos`): AppKit, `StreamView`, `MetalSurface`, `RelativeMouse`, `KeymapMac` (kVK → HID table, ISO layout); gamepads go through SDL, read by the core's single reader (libkynput built without its own, several computers at once), and the combination is followed in the core's input chain (`gamepad_gate.rs`). Clipboard through `NSPasteboard`. Several computers at once ([plusieurs-ordinateurs.en.md](plusieurs-ordinateurs.en.md)): several `SessionEngine`s in the app, one per window, each registered with the core's registry when it starts (`Params.focusName`); the app's session manager (`Sessions.swift`) only tells the registry which window comes to the front, “Keep sound” and “Next computer”, then reads its state back for the interface (below). The Mac's clipboard goes through the core's bridge (`ClipboardBridge` on the `NSPasteboard` callbacks of `kn_input_new`), which the session pauses itself.
- **Apple TV** (`apps/tvos`): KyberKit's shared files without the AppKit ones, plus `KyberKitTV`: UIKit session view, Metal surface, `GamepadBridge` and `KeyboardMouse` (GameController).
- **iPhone and iPad** (`apps/ios`): the same shared files, the Apple TV's Metal surface, `KeyboardMouse` and `GamepadBridge`, and the touch session view `KyberKitIOS/StreamView`. Clipboard through `UIPasteboard`, read only when the computer asks for it (`pasteboard_reading_asks_user`). See [apps/ios/README.en.md](../apps/ios/README.en.md).

On Apple TV, iPhone and iPad, `GamepadBridge` follows the combination itself before sending (menu, gamepad as mouse, long press): it keeps a `PadCombo` held by the core (`kn_combo_*`, with its own thread for the 250 ms deadline); the input chain has its combination turned off. The pointer held by the device (remote, gamepad, mouse, touch) is the position of the core's `PointerLayer` (`holds_position`).

The sound, input and clipboard tests are the core's: `cargo test -p kybernow-core` (see [apps/core/README.en.md](../apps/core/README.en.md)).

## The bridge: `apps/apple`, crate `kybernow-apple`

A hand-written C API (`kn_` prefix), `kybernow.h` header produced by cbindgen through `cargo cinstall` (cargo-c). Swift imports it through the `CKyberNow` module (`Vendor/KyberNow/include/module.modulemap`).

API rules:

- **Opaque objects** (`KnConsole`, `KnSession`, `KnInput`, `KnPointer`, `KnAudio`, `KnCombo`) created and freed by the core; no Rust structure is exposed.
- **Composite results as JSON** (`char *`, freed by `kn_string_free`): Admin's replies, a session's settings. Admin's JPEG preview comes as bytes, freed by `kn_bytes_free`. Each second's measurements (`KnSecond`) and packets (`KnPacket`) are flat C structs: hot path, no copy, no allocation.
- **Callbacks** (`KnPlatform`): function pointers and a `userdata`; the core calls them from its own threads (session thread, Kyber's network thread for packets). Swift hops to the main thread for what touches the interface; packets go straight to the decoder.
- **Packets**: `video_packet` and `audio_packet` receive a `KnPacket` (stream number, format, configuration or frame, keyframe, pts, data in place, hole with the number of missing samples); a new stream number, a new decoder; the last call of a stream carries `KN_PACKET_CLOSED`, after which the core never calls again for that stream: Swift then stops its decoder or its sound output.
- **Input chain**: `input_pipeline()` returns the kynput chain of a `KnInput` (`kn_input_new`, on the view's `KnPointer` pointer layer, `kn_input_kynput`); the core passes it to Kyber with the picture session. Swift only hands over the captured events (`kn_input_key`, `mouse`, `mouse_button`, `wheel`, `type_text`, `gamepad_*`, held and resynced modifiers) and draws the pointer (`on_changed` of `KnPointerCallbacks`, shape in premultiplied ARGB); interface callbacks (combination, navigation keys, inputs connected, rumble, clipboard) go through `KnInputCallbacks`.
- **Sound**: one `KnAudio` per stream (`kn_audio_new`, the output's channel order) receives the packets (`configure`, `decode`, `conceal`); the output's real-time thread pulls samples with `kn_audio_fill` and measurements with `kn_audio_take_stats`.
- **Latency**: the Metal renderer tells the core each frame shown (`kn_session_frame_displayed`, instants in µs on `CLOCK_MONOTONIC`, `kn_now_micros`), replaced, the bytes received and the holes; every second the core returns a `KnSecond` (median, path of a frame, losses, rejected measurements, round trip, bitrate) through `on_second`.
- **States** (`on_status`): preparing, connecting, first images, picture, reconnecting (attempt, maximum), ending, ended (with the reason when it was not wanted, and Admin's report: displays and sound restored). The reason for a failure is already in `error` at `KN_STATUS_ENDING` (the same as at `KN_STATUS_ENDED`, which waits for Admin's answer): the app knows at once it is a failure; null for a wanted end.
- **Notices** (`on_notice`): what the session shows in a capsule, without text (Swift translates it): picture relaunched, computer's mode changed or back (with the size), fallback (level), adapting to the screen (requested, done, refused), “Restore” offered or withdrawn; and, on the connection screen, the Station restarting (below).
- **The connection's last resort**: Admin has answered, but the picture does not arrive despite the session's own repairs, or the connection to Kyber fails. The core closes the attempt with Admin, restarts the Station once (`station_restart` without `force`: never if another device is in session, nor too soon, nor with a Station that is too old), waits for it (`info` every 2 s, 90 s at most), then runs the session again from the start, virtual display included. Never once a picture has been shown. The sequence and its safeguards: [apps/core/README.en.md](../apps/core/README.en.md). Swift receives `KN_STATUS_CONNECTING` then the notice `KN_NOTICE_STATION_RESTARTING` (7): the connection screen shows “The Station is restarting…” until the next `on_status` (`KN_STATUS_PREPARING` if it comes back, `KN_STATUS_ENDING` then `KN_STATUS_ENDED` otherwise). It has no C state of its own: `SessionEngine` takes an unknown state for the end of the session; an app that ignores the notice stays on “Connecting”. `recovery.restart_station` set to `false` in the JSON of `kn_session_start` turns it off (true when missing). If the picture still does not come, the end reason says so (“…, even after restarting the Station”), as it does for a Station that is not back in time.
- **Multiple displays** (Mac; contract: [multi-ecrans.en.md](multi-ecrans.en.md), Rust API: [apps/core/README.en.md](../apps/core/README.en.md#multiple-displays-srcscreensrs-srcsessionrs-srcinputpipeliners)): `kn_session_start` also takes `screens` in its JSON, for every session: `list`, the device's displays (mirrors grouped; `x`, `y`, `width`, `height`: frame in points, y pointing down, Cocoa's coordinates converted; `pixel_width`, `pixel_height`: native resolution; `refresh`; `primary`: the one with the menu bar), `current` (the window's display: “This display”), `limit_4k`, `custom_resolution`, `setting` (`auto`, `this`, `all`), `max_screens` (`virtual_display.max_screens` from `kn_console_info`, absent: 1) and `virtual_display_available` (`virtual_display.available`, absent: true). The core derives the number of displays from it, at the start and when the profile changes (`kn_session_set_settings`); `mode` is the mode of “This display”. In order, at each image start: `on_display` (the primary display, as before), then `on_screens` (`KnStreamScreen`: `screen`, the index in `list`; `display`, the computer's display with its `id` and size in pixels; `refresh`; `primary`, always the first; and `not_created`, the indexes of the displays the computer could not create: “The computer could not create this display.”; displays removed because they stayed silent are there too; one display and an empty `not_created`: single-display session, single-display Station or only the primary accepted, the other windows do not open or close, without a message), then `input_pipeline`: Swift creates the `KnInput` there on the primary window's pointer layer (the primary display's `display_id`), then calls `kn_input_set_screens` with one `KnInputScreen` per display (`screen`, `display_id`, size, its window's `KnPointer`). Image packets carry `KnPacket::screen`: one decoder and one renderer per display. With the desktop mouse, each window sends `kn_input_mouse_on(i, screen, x, y)` (pixels of its computer display); the computer's pointer arrives through `on_changed` of the layer of the display it is on, hidden on the others (Auto mouse: `kn_pointer_summary` over every window's layer, the core's rule, then `kn_mouse_wants_relative`). `kn_session_frame_displayed` for the primary display only; `kn_session_bytes_received` for all; `kn_session_keyframe_lost` from any decoder (the core waits for every stream's first data before asking for a keyframe). Mac displays changed during the session: `kn_session_set_screens(s, json)` (same JSON as `screens`); a profile chosen during the session may also change the number of displays, which follows at once; the connection then resumes at `KN_STATUS_PREPARING` on the primary display, then `on_screens` comes back; it also comes back when the computer changes a display's size, or a display is removed (silent for 4 s, or refused by Kyber: a new attempt with the primary display alone). Setting and home screen, same rules as Windows and Linux: `kn_screens_setting_enabled(custom_resolution, virtual_display)` (false: “Displays” setting inactive, on “This display”); `kn_screens_session_plan(json, profile, virtual_display, codec)` returns the plan (at least two displays: `device`, mode, position) or null for one display: its length makes the home line and the windows to open, with the same calculation as the session; `kn_screens_primary_index(json)`: the display showing the connection screen. Without `screens`, nothing changes: `KnPacket::screen` is 0 and `on_screens` is never called.
- **Commands**: stop, keyframe lost or back, new settings (profile from the bar), bitrate cap (occluded window), picture frozen by the app (`kn_session_set_hidden`: the “no picture” watch waits for its return), size of the decoded frames (`kn_session_decoded_size`), chosen display, new mode (adapting to the device's screen), mode restore.
- **Station** (the “Station” section of a computer's settings): the JSON of `kn_console_info` carries `station` (`version`, `update`: `available`, `version`, `installable`, `requires_setup`, `installing`; `restarting`), null with a Station 0.4.9 or older, for which the app offers neither restart nor update. `kn_console_admin_url` returns `https://address:port/`, to open in the browser. `kn_console_station_restart(c, device_id, force, out, error)` restarts the whole Station (the Kyber server and Admin, about a minute) and returns `{"ok": true}`; `kn_console_station_update` (same parameters) starts the same installation as “Install now” in Admin and returns `{"version": …}` in `out`. Both block: 15 s at most for the restart, as long as Admin takes to download and verify the package for the update (a few minutes at most); never on the main thread. `device_id` names the device in Admin's activity feed, `force` cuts off a session in progress. A refusal returns `KN_STATION_IN_SESSION` (a device is in session: call again with `force`), `KN_STATION_TOO_SOON` (one restart per minute, or too many failed attempts), `KN_STATION_NOTHING_TO_INSTALL`, `KN_STATION_REQUIRES_SETUP` (installer, on the computer), `KN_STATION_BUSY` (installation or restart under way) or `KN_STATION_UNSUPPORTED` (Station 0.4.9 or older), with the message in `error` and the details as JSON in `out` (`kind`, `message`, `device`: the device in session, `seconds`: the wait); anything else, the codes of the other calls.
- **Wake on LAN**: the JSON of `kn_console_info` carries `wake`, the computer's network cards, Ethernet first (`mac`, `ipv4`, `broadcast`, `kind`: `ethernet` or `wifi`, `armed`: Windows lets it wake the computer, null if unknown, `name`), an empty list with a Station older than 0.5.0. The app keeps this JSON for each computer when the list is not empty, and hands it to `int32_t kn_wake(const char *targets_json)` to offer “Wake the computer” once it is off (a single target, for example `{"mac": "…", "ipv4": "…"}`, works too). The magic packet goes to each card's subnet broadcast address, to 255.255.255.255 and to its last IPv4 address, directly; `KN_OK` as soon as one packet has gone out, `KN_WAKE_NO_TARGET` without a readable target, `KN_ERROR` if none went out. Quick, but off the main thread. **Pitfall**: on iPhone, iPad and Apple TV, broadcasting requires the `com.apple.developer.networking.multicast` entitlement, which Apple grants on request; without it, broadcasting is refused (often `EHOSTUNREACH`, logged) and only direct sending goes out, which does not always wake the computer (the network must still be able to reach the address). `kn_wake` succeeds anyway: the app has nothing to tell apart. On the Mac there is no restriction (see [apps/core/README.en.md](../apps/core/README.en.md#wake-on-lan-srcwakers)).
- **Several computers at once** (Mac; contract: [plusieurs-ordinateurs.en.md](plusieurs-ordinateurs.en.md), Rust API and rules: [apps/core/README.en.md](../apps/core/README.en.md#several-computers-at-once-srcfocusrs-srcgamepads-srcjournalrs)). One `KnSession` per computer, each with its `KnPlatform`, its windows, its `KnInput` and its `KnAudio`.
  - Registry: `int64_t kn_focus_register(const KnSession *s, const char *name)` registers the session (its computer's name, at the start of its log lines) and makes it active; it returns its identifier (positive, the same if it is already registered), or -1 beyond `kn_focus_max()` (4): “Connect” is then disabled (“Four computers at most at the same time.”, `kn_focus_count()`). `kn_focus_activate(id)` when its window becomes the main window; `kn_focus_set_keep_sound(id, bool)` and `kn_focus_keep_sound(id)` for the “Keep sound” button; `kn_focus_next()` for ⌃⌥⌘O (the next session in opening order: bring its window to the front, then `kn_focus_activate`); `kn_focus_active()`; `kn_focus_unregister(id)` at the end of the session (window closed, “Disconnect”, end), before `kn_session_free`. On every change the core cuts the inputs and sound of the other sessions (unless “Keep sound”) and gives everything back to the active one.
  - Sound: `kn_session_attach_audio(s, audio)` for each `KnAudio` of the session, as soon as it is created (sound goes to Swift, the core does not see it go by); it then follows the session's state (20 ms fade). Inputs: nothing to plug, the core finds the `KnInput` created in `input_pipeline`.
  - Directly, without the registry: `kn_session_set_active(s, bool)`, `kn_session_set_muted(s, bool)` (and `kn_session_is_active`, `kn_session_is_muted`), kept from one image to the next; for a single chain or engine, `kn_input_set_active` (`kn_input_is_active`) and `kn_audio_set_muted`. A single session is active and audible: Apple TV, iPhone and iPad have nothing to call.
  - Displays of one more session (the core's rule, `screens::screens_for_extra_session` and `screens::extra_session_window`): `char *kn_screens_for_extra_session(const char *screens)`, same JSON as `screens` in `kn_session_start` (`current`: the active window's display), returned on “This display” (free with `kn_string_free`); `bool kn_screens_extra_session_window(const char *screens, KnExtraWindow *out)`: the window “centred, two thirds of that display, in 16:9” on the `current` display, the picture area's frame in the device's logical space (y down) and a `KnMode` in the display's pixels, to ask the computer for (width and height multiples of 8, the frame being that mode's). The Mac app opens its window there (title bar around it) and takes the mode from it.
  - Gamepads: nothing to call, the core's reader starts with the first `KnInput` and closes 5 s after the last chain ends (SDL then gives the gamepads back: player light, HIDAPI mode of Sony and Nintendo gamepads). `kn_gamepads_start_sdl()` would keep it open for the whole life of the app, gamepads included: only to read gamepads outside a session; false on Apple TV, iPhone and iPad (no SDL). A session going behind stops the rumble it had started. `gamepads_from_app` stays false on the Mac: the gamepad hook (combination, `kn_input_set_gamepad_captured` for the bar) sees the reader's gamepads like kynput's, and the combination stays followed by the chain (do not call `kn_input_set_combo_enabled(core, false)` on the Mac). Rumble is played by the core (`on_rumble` has nothing to do on the Mac).
- **KyberNow Share** (contract: [kybernow-share.en.md](kybernow-share.en.md), texts: [link-ui.en.md](link-ui.en.md) “Sharing”, Rust API and rules: [apps/core/README.en.md](../apps/core/README.en.md#kybernow-share-srcsharers-srcsessionrs-srcinputpipeliners)), in `apps/apple/src/share.rs`:
  - Joining: `int32_t kn_share_join(const char *targets_json, const char *request_json, const char *capabilities_json, char **out, char **error)` sends the code to all the given Stations at once (`[{"host", "port", "fingerprint"}]`: the computers found on the network, as for pairing, or the link's one); `request_json`: `{"code", "name" (the first name), "device" (the device's identifier), "app" (mac, ios, tvos)}`; `capabilities_json` (`{hevc, hevc444, av1}`, or null) checks that a format is possible (the host's, otherwise a readable one: a picture of its own), the guest leaving at once if none is. `out`: `{"target": {host, port, fingerprint}, "joined": {…}}`. Refusals: `KN_SHARE_NO_SHARE` (20), `KN_SHARE_FULL` (21), `KN_SHARE_TOO_MANY` (22), `KN_SHARE_UNREADABLE` (23), `error` holding the text to show; otherwise the other calls' codes. Blocking, 6 s at most. `kn_share_leave(found_json)` (the `out`) if the app gives up before opening the session.
  - `char *kn_share_parse_link(url)`: `{"host", "port", "fingerprint", "code"}` of a `kybernow://join?…` or web client link, null otherwise; `kn_share_normalize_code` (six digits or null), `kn_share_format_code` (“123 456”).
  - Guest session: `kn_session_start` with `guest` (`{"joined": <joined from kn_share_join>, "capabilities": {…}}`), `console_host`, `console_port` and `console_fingerprint` from `target` (`user`, `password` and `mode` optional). `KnPlatform` callbacks added at the end (null: ignored; Swift zero-initialises the struct): `on_share_role(userdata, role, previous)` (two independent rights: `KN_SHARE_ROLE_SPECTATOR` none, `KN_SHARE_ROLE_PLAYER` the gamepads, `KN_SHARE_ROLE_KBM` the keyboard and mouse only, `KN_SHARE_ROLE_PLAYER_KBM` both; “Player” in the bar: at least one right; `previous` −1 at the start), `on_share_end(userdata, end, text)` (`KN_SHARE_END_STOPPED`, `KN_SHARE_END_REMOVED`, `KN_SHARE_END_UNREADABLE`, right before `KN_STATUS_ENDING`, whose `error` holds the same text; never “Take back control”). A spectator has no input chain: `input_pipeline` is not called; when it is given a right, the picture is restarted and `input_pipeline` is then called (with the keyboard and mouse only, the chain exists without gamepads). Between two roles that each have a chain, the picture is not restarted. Its rights are held by the core in the `KnInput`: Swift sends everything as usual.
  - A guest's picture quality (contract: “A guest's picture”): `KN_SHARE_QUALITY_AUTO` (0), `KN_SHARE_QUALITY_HOST` (1), `KN_SHARE_QUALITY_1080P60` (2), `KN_SHARE_QUALITY_720P30` (3), `KN_SHARE_QUALITY_2160P60` (4), to show in the order Auto, same as host, 4K, 1080p, 720p; `kn_share_quality_label(quality)` (“Auto”, “Same as host”, “4K · 60 Hz”, “1080p · 60 Hz”, “720p · 30 Hz”). On “Join”, `kn_share_join`'s `request_json` carries `"quality"` (`auto`, `host`, `1080p60`, `720p30`; `auto` by default) and, for `auto`, `"auto"`: `kn_share_auto_quality(screen_json, decoder_json, host_json)` (the window's screen like a `screens.list` entry, the decoder `{hevc, hevc444, av1, max_width, max_height, max_fps}`, the shared display or null) returns `{width, height, fps, codecs, yuv444}`. During the session, `kn_session_set_share_quality(s, quality)`: Kyber moves the guest's picture only, nothing to restart; more than one change a second, the core tries again once after Admin's delay, with no error; with Auto, the core sends again `kn_share_join`'s `auto`, kept in `joined` (to pass as is to `guest.joined`). The picture received comes through the `on_share_image(userdata, image_json, previous_json, notice)` callback added at the end of `KnPlatform` (JSON `quality`, the quality asked for, then `width`, `height`, `fps`, `codec`, `follows_host`, `reason`: `asked`, `capped`, `limit`, `lag`, each `null` as long as Kyber knows nothing; `previous_json` null at the start; `notice`: link-ui's short notice, only on a known drop or the limit, or null); `kn_share_image_label(image_json)` gives “1080p · 60 Hz” for the bar (and for `guests[].image` on the host's side), null while the size is not known. “Auto” is settled by Admin from `auto`. A host format the device cannot play no longer prevents joining: the core asks for a readable format and Kyber makes a picture of its own; the decoder must follow a size change during the stream (new SPS/PPS).
  - Host: `kn_share_availability(info_json)` (`KN_SHARE_UNSUPPORTED`, `KN_SHARE_DISABLED`, `KN_SHARE_AVAILABLE`) and `kn_share_availability_text`; `kn_console_share_open`, `kn_console_share_state`, `kn_console_share_code` (JSON in `out`), `kn_console_share_guest(c, guest, role, error)` (`KN_SHARE_ROLE_*`; `kn_share_role_with_pads(role, bool)` and `kn_share_role_with_kbm(role, bool)` give the role for “Give / Take back controllers” and “Give / Take back keyboard and mouse”, the other right as is), `kn_console_share_kick(c, guest, error)`, `kn_console_share_close(c, error)`, blocking, on the computer's `KnConsole`; the guest list also comes through `on_guests(userdata, share_json)` during the session (null without a share), when it changes.
- **Log**: the core writes through the `log` crate; `kn_set_log_callback` sends it to `KyberLog` (unified log, `core` category).

## Building and shipping

The core builds the `kyclient` Rust crate from Kyber's sources (`third_party/kyber-desktop/kysdk`), with the patches in `apps/macos/kyber-patches` (see [kyber-changes.en.md](kyber-changes.en.md)).

**Mac**: dynamic library `libkybernow.dylib`, in `apps/macos/Vendor/Frameworks`, embedded and signed by `embed-kyber.sh` like the other libraries.

```bash
apps/macos/scripts/vendor-kyber.sh      # once: Kyber SDK → Vendor/
apps/macos/scripts/build-kyclient.sh    # libkynput and libkyclient with the patches → Vendor/
apps/apple/scripts/build-apple.sh       # kybernow-core + kybernow-apple → Vendor/Frameworks/libkybernow.dylib, Vendor/KyberNow/include/kybernow.h
cd apps/macos && xcodegen generate && xcodebuild -scheme KyberNow -configuration Debug -derivedDataPath build build
```

`build-apple.sh` builds for `aarch64-apple-darwin` with the repository's stable Rust and refuses to run while the app is open (in a git worktree: `KYBERNOW_IGNORE_RUNNING=1`, like `build-kyclient.sh`). The bridge links libkynput and libvlc from the Kyber SDK (input chain; player never called), and the SDK's `libSDL2-2.0.0.dylib` (the core's gamepad reader, `sdl` feature on macOS only), already in `Vendor/Frameworks`. `build-kyclient.sh` builds libkynput without its SDL reader: the two scripts go together (a libkynput that still has its own keeps kynput's gamepads, and the core's reader does not start by itself).

**Apple TV and iPhone/iPad**: static library in `apps/<platform>/Vendor/KyberNow.xcframework` (device and simulator), from `apps/apple/scripts/build-apple-mobile.sh tvos|ios`, deployment 18.0.

- Apple TV: Rust nightly and `-Zbuild-std` (tier 3 target). libkynput, libopus and VLC's empty functions come from Kyber's SDK for tvOS (`Vendor/KyberSDK.xcframework`, from `apps/tvos/scripts/build-kyber-tvos.sh`), linked alongside.
- iPhone and iPad: stable Rust. No separate Kyber SDK: libkynput (built by `apps/core/scripts/build-apple.sh --target aarch64-apple-ios` and `--target aarch64-apple-ios-sim`), libopus and VLC's empty functions go into the same library as the core; kynput's header goes into `Vendor/include` (`CKyber` module).

`apps/core/scripts/build-apple.sh` checks that the core's dependency chain builds for each Apple target. `scripts/release.sh` builds the core for all three apps; the Apple TV's and the iPhone/iPad's `Vendor/` is published with each release (`KyberSDK-tvOS.zip`, `KyberSDK-iOS.zip`), which the CI and the `sideload.sh` scripts pick up. Details and pitfalls: [build-notes.en.md](build-notes.en.md#the-rust-core-of-the-apple-apps-appsapple).
