# Cœur de KyberNow Link (`kybernow-core`)

[English](README.en.md) · Français

Ce que les apps KyberNow Link ont en commun, écrit une fois en Rust : le dialogue avec KyberNow Admin, la session Kyber, les profils et le débit, la latence, les mises à jour, le module d'entrées, le moteur de son, et plusieurs ordinateurs à la fois (registre des sessions, lecteur de manettes unique). Toutes les apps y reposent : Windows, Linux et webOS ([apps/windows](../windows/README.md), [apps/linux](../linux/README.md), [apps/webos](../webos/README.md)) directement, Android ([apps/android](../android/README.md)) par JNI (`apps/android/jni`), Mac, Apple TV, iPhone et iPad ([apps/macos](../macos/README.md), [apps/tvos](../tvos/README.md), [apps/ios](../ios/README.md)) par le pont C `apps/apple` ([docs/coeur-apple.md](../../docs/coeur-apple.md)).

Le cœur ne dépend d'aucun système : rien n'y appelle AppKit, UIKit, Win32 ni Core Audio (seul le lecteur de manettes peut ouvrir SDL lui-même, feature `sdl`, sur Mac et Windows). Ce que la plateforme fournit passe par des traits (la fenêtre, les décodeurs, la sortie du son et les entrées par `session::Platform` ; l'horloge, le presse-papiers et les rappels vers l'interface par les traits du module d'entrées ; la sortie du son tire elle-même le son du moteur). Les briques de Kyber 0.29 viennent de `third_party/kyber-desktop/kysdk` avec les correctifs KyberNow (`apps/macos/kyber-patches`), voir [apps/windows/README.md](../windows/README.md).

## La Station dans les réglages d'un ordinateur

La rubrique « Station » des réglages d'un ordinateur (Ouvrir Admin, Redémarrer la Station, Mettre à jour la Station) passe par `console.rs` :

- `Info::station` (`GET /api/stream/info`) : `StationInfo` avec la version de la Station, sa mise à jour (`StationUpdate` : `available`, `version`, `installable`, `requires_setup`, `installing`) et `restarting`. `None` avec une Station 0.4.9 ou plus ancienne : l'app n'y propose ni redémarrage ni mise à jour.
- `Console::admin_url()` : `https://adresse:port/` (IPv6 entre crochets), à ouvrir dans le navigateur ; le certificat d'Admin est auto-signé, le navigateur demande de l'accepter la première fois.
- `Console::station_restart(device_id, force)` : redémarre la Station entière (le serveur Kyber et Admin, environ une minute, Admin ne répond plus pendant ce temps). `Console::station_update(device_id, force)` : la même installation qu'« Installer maintenant » dans Admin, rend la version installée ; Admin télécharge et vérifie le paquet avant de répondre (300 s de délai). `device_id` : l'identifiant de l'appareil, qui le nomme dans le fil d'Admin (il ne donne aucun droit : tout appareil appairé peut redémarrer et mettre à jour) ; `force` : même si un appareil est en session, qui est coupée.
- Refus (`StationError`) : `InSession` (un appareil est en session, `device` : son nom ; refaire l'appel avec `force`), `TooSoon` (un redémarrage par minute, ou trop d'essais ratés depuis cette adresse ; `seconds`), `NothingToInstall` (Station à jour, ou version refusée), `RequiresSetup` (la version s'installe avec l'installateur, sur l'ordinateur), `Busy` (installation ou redémarrage déjà en cours), `Unsupported` (Station 0.4.9 ou plus ancienne : elle répond la page d'Admin, ou 404), `Other` (`ConsoleError`). Le message vient d'Admin, dans la langue de l'app. `kind()` et `to_json()` donnent le refus aux ponts (`kind`, `message`, `device`, `seconds`).

## Dernier recours de la connexion : la Station redémarrée

Quand une connexion n'aboutit vraiment pas, la session redémarre elle-même la Station, comme « Redémarrer la Station » des réglages, puis réessaie (`src/session.rs`, `Recovery::restart_station`, vrai par défaut, sans réglage dans les apps).

- **Quand.** Admin a répondu (`prepare` a réussi) et aucune image n'a encore été montrée (`LatencyTracker::any_displayed`), mais l'image n'arrive pas malgré les réparations de la session (image clé redemandée, flux relancé trois fois, repli : débit réduit puis 4:2:0), Kyber refuse l'image (`StreamingStartFailed`), la chaîne d'image échoue trois fois, ou aucun écran utilisable n'apparaît ; ou bien la connexion à Kyber échoue après ses propres essais : réseau, délai, erreur du serveur ou du protocole (`ControlPlaneConnectFailed`), connexion au flux impossible, reconnexion épuisée, connexion fermée par Kyber.
- **Jamais** : Admin injoignable ou qui refuse le compte (`prepare` ou `end` en échec), compte que Kyber ne connaît pas encore (`Unauthorized` : Admin redémarre déjà Kyber pour les comptes en attente quand personne d'autre ne s'en sert), certificat de Kyber différent, erreur de l'appareil, annulation par l'utilisateur, fin demandée par Admin ou par un autre appareil qui prend la main, session établie (une image a été montrée : elle garde ses reprises, reconnexion comprise), `restart_station` faux.
- **Déroulé.** La tentative est close comme une fin de session (`POST /api/stream/end` : écrans et son rétablis ; sans cela, Admin compterait cet appareil comme en session et refuserait). Puis `station_restart(device_id, force = false)` : Admin note dans son fil quel appareil a redémarré la Station, et refuse si un autre appareil est en session (`InSession`), si c'est trop tôt (`TooSoon`), avec une Station trop ancienne (`Unsupported`) ou sur toute autre erreur ; la session échoue alors avec sa raison, comme sans ce recours. Accepté, la plateforme reçoit `Status::StationRestarting` ; le cœur interroge `info` toutes les 2 s jusqu'à ce qu'Admin réponde avec `station.restarting` faux, 90 s au plus. Revenue, la session repart du début : `Preparing`, `prepare` (l'écran virtuel est recréé), Kyber, image, avec les réglages de départ (le repli repart de zéro).
- **Une fois par connexion.** Si l'image ne vient toujours pas : « {raison}, même après un redémarrage de la Station » (`session.after_station_restart`) ; si la Station ne revient pas dans les 90 s : « la Station tarde à revenir après son redémarrage : ouvrez Admin pour en savoir plus » (`session.station_not_back`). L'utilisateur peut annuler pendant l'attente : la session s'arrête sans erreur.
- **Pour les apps.** `Status::StationRestarting` arrive entre l'étape en cours et `Preparing` (ou `Ending`) ; l'écran de connexion affiche « La Station redémarre… » ([docs/link-ui.md](../../docs/link-ui.md), « Connexion »). Une app qui ne le montre pas encore reste sur l'étape « Connexion » : Apple reçoit `KN_STATUS_CONNECTING` puis l'avis `KN_NOTICE_STATION_RESTARTING` ([docs/coeur-apple.md](../../docs/coeur-apple.md)), Android l'état 1 puis l'avis 7 (`SessionListener.NOTICE_STATION_RESTARTING`), l'interface Windows `session-status` à `connecting` puis l'événement `session-station-restarting` (`ui/src/lib/api.ts`), Linux et webOS leur étape « Connexion ». Les ponts lisent `recovery.restart_station` dans le JSON de la session (vrai s'il manque) ; la ligne de commande Windows et les bancs d'essai peuvent le couper.

## Réveil par le réseau (`src/wake.rs`)

Les apps proposent « Réveiller l'ordinateur » quand il est hors ligne, sans rien à saisir : Admin (Station 0.5.0 et suivantes) donne ses cartes réseau dans `Info::wake`, l'app les garde pour chaque ordinateur et le cœur envoie le paquet magique.

- `WakeTarget` : une carte, `mac` (`AA:BB:CC:DD:EE:FF`), `ipv4` (sa dernière adresse), `broadcast` (la diffusion de son sous-réseau), `kind` (`ethernet`, `wifi`), `armed` (Windows la laisse réveiller l'ordinateur ; `None` : inconnu) et `name`. Sérialisé tel quel (serde, champs facultatifs sauf `mac`, champs inconnus ignorés) : les apps Rust le stockent dans leur fichier, les autres gardent le JSON de `wake`. `Info::wake` est vide avec une Station plus ancienne, et la lecture est tolérante (`wake` illisible : liste vide, le reste d'`info` est lu). L'app remplace les cibles gardées par celles d'un `info` réussi quand la liste n'est pas vide. `WakeTarget::from_mac(mac, ipv4)` : une cible d'après une adresse saisie (`3C:7C:…`, `3c-7c-…`, `3c7c.3f12.abcd`).
- `send(&targets)` : le paquet magique (6 × `FF`, puis 16 fois l'adresse MAC, 102 octets) de chaque carte, en UDP avec `SO_BROADCAST`, ports 9 et 7, vers `destinations(&targets)` : la diffusion de chaque sous-réseau (celle d'Admin, sinon le /24 de l'adresse connue), 255.255.255.255, puis la dernière adresse IPv4 de chaque carte, en direct. Un refus sur une adresse est noté au journal et n'arrête rien ; `Ok(n)` dès qu'un paquet est parti, `WakeError::NoTarget` sans adresse MAC lisible, `WakeError::Network` si aucun n'est parti (message dans la langue de l'app). Pas d'attente réseau, mais à appeler hors du fil de l'interface. `targets_from_json` lit pour les ponts une liste de cibles, une cible seule ou l'info entière.
- `parse_mac`, `format_mac`, `magic_packet`, `broadcast(ip, prefix)` : les briques, testées (`cargo test -p kybernow-core wake`) ; `envoi_reel`, ignoré par défaut, envoie vraiment vers une carte fictive (`-- --ignored`).

**Piège Apple.** Sur iPhone, iPad et Apple TV, envoyer vers une adresse de diffusion (le sous-réseau comme 255.255.255.255) demande l'autorisation `com.apple.developer.networking.multicast`, qu'Apple accorde sur demande (formulaire du compte développeur, puis l'autorisation dans les fichiers `.entitlements`). Sans elle, l'envoi en diffusion échoue, souvent avec `EHOSTUNREACH`. L'envoi direct vers la dernière adresse IPv4 passe sans elle, mais ne réveille que si le réseau sait encore joindre cette adresse (cache ARP du routeur ou du commutateur, carte en veille qui répond encore à l'ARP), ce qui n'est pas toujours le cas après un arrêt complet. C'est pourquoi `send` tente toujours l'envoi direct en plus de la diffusion et réussit dès qu'un paquet part : sans l'autorisation, le réveil marche parfois, avec elle, comme ailleurs. Sur Mac, pas de restriction (l'autorisation « Réseau local », déjà demandée pour joindre Admin, suffit).

## Multi-écrans (`src/screens.rs`, `src/session.rs`, `src/input/pipeline.rs`)

Une session peut prendre tous les écrans de l'appareil : un écran virtuel par écran de l'appareil, placés de la même façon, chacun affiché dans sa fenêtre (contrat commun : [docs/multi-ecrans.md](../../docs/multi-ecrans.md)). Les apps Mac, Windows et Linux s'en servent ; la session à un écran garde exactement son API, et les apps qui ne gèrent pas le multi-écrans n'ont rien à changer.

**Les écrans de l'appareil et ce qui décide de leur nombre.** `Screens { list, current, limit_4k, custom_resolution, setting, max_screens }` : les écrans (`DeviceScreen`, ci-dessous), « Cet écran » (`current`, l'écran de la fenêtre de l'app, celui d'une session à un écran), « Au plus 4K », une définition sur mesure, le réglage « Écrans » (`DisplaysSetting` : `Auto`, `This`, `All`, gardé en `auto`, `this`, `all`), et le nombre d'écrans que la Station sait créer (`virtual_display.max_screens` de `GET /api/stream/info`, `VirtualDisplayInfo::max_screens()` ; absent : 1). `DeviceScreen { x, y, width, height, pixel_width, pixel_height, refresh, primary }` : le cadre de l'écran dans le repère logique de l'appareil, y vers le bas (points sur Mac, après conversion du repère de Cocoa ; bureau de Windows ; `SDL_GetDisplayBounds` sous Linux), sa définition native en pixels (avant « Au plus 4K »), sa fréquence, et s'il est principal (aucun : le premier). Des écrans en recopie comptent pour un : l'app n'en donne qu'un. Les deux types passent tels quels en JSON (serde, champs facultatifs) pour les ponts.

**Le plan** (`screens::plan(&screens, codec)`, sans regarder le réglage) : quatre écrans au plus et pas plus que `max_screens`, le principal en premier, chacun avec son écran de l'appareil (`device`, index dans `list`), son mode et sa position en pixels sur le bureau de Windows (`PlannedScreen`).

- Définition (`screens::fit`) : « Au plus 4K » ramène chaque écran à 3840 × 2160, l'H.264 à 4096 de large (l'encodeur de NVIDIA s'y arrête), sinon 7680 × 4320 ; proportions gardées, arrondi au pair, comme `DisplayInfo.mode` de l'app Mac.
- Fréquence (`screens::refresh`) : l'écran principal garde la sienne ; les autres sont à 60 Hz, moins si leur écran ne va pas jusque-là.
- Position (`screens::layout`) : le principal en (0, 0) ; les autres collés de proche en proche, du même côté, au voisin déjà placé avec lequel ils partagent un bord sur l'appareil, avec le décalage de l'appareil converti à l'échelle pixels / unités logiques du voisin ; 64 pixels de bord commun au moins ; jamais de chevauchement (l'écran glisse le long du bord, et parmi ses voisins possibles, le cœur prend celui qui le fait le moins glisser) ; un écran qui ne touche rien se colle au plus proche, du côté de l'écart le plus grand. Au-delà de quatre écrans (ou de `max_screens`), ceux qui sont pris sont les plus proches du principal, de proche en proche. `plan_excluding(&screens, codec, &retirés)` refait le plan sans des écrans retirés en session (jamais le principal), les index restant ceux de l'appareil.

**Une seule règle pour le nombre d'écrans** : `screens::session_plan_for(&screens, &réglages, écran_virtuel_demandé)`, le calcul de la session, à utiliser aussi pour l'accueil et le réglage. Il compte l'écran virtuel s'il est demandé et utilisable (`Screens::virtual_display_available`, de `virtual_display.available` d'`info`), et le profil donné par `screens::screens_profile(&réglages, Screens::capabilities)` : `None` (« Personnalisé ») sans profil, ou quand les réglages s'écartent de `StreamSettings::for_profile` pour ces capacités ; le profil envoyé à la Station ne change pas. Station qui prépare sans écran virtuel ou sans `screens` : plan vidé pour toute la session, « Cet écran ». Session à un écran : l'écran du flux suit « Cet écran » (`set_screens`), sans relancer l'image ; une seule cible d'entrées : tout pointeur à la couche principale. Une session refaite attend la préparation en cours.

**Le réglage « Écrans », l'accueil et le nombre d'écrans** ([docs/link-ui.md](../../docs/link-ui.md)) : `DisplaysChoice { setting, profile, custom_resolution, virtual_display }` (`Screens::choice(profile, virtual_display)`). `setting_enabled()` : faux avec une définition sur mesure ou sans écran virtuel ; le réglage est alors inactif et montre « Cet écran » (`shown_setting()`). `all_displays()` : Tous les écrans ; Auto prend tous les écrans en Bureau et Max, un seul en Jeu et en Personnalisé. `screens::session_plan(&screens, profile, virtual_display, codec)` rend le plan quand la session prendra au moins deux écrans, sinon `None` (réglage, profil, Station qui n'en crée qu'un, un seul écran) : la ligne de l'accueil (« 3 écrans, à la taille de ceux de cet appareil » : la longueur du plan) et les fenêtres à ouvrir viennent de lui, et la session fait le même calcul. L'écran principal de l'appareil (celui de l'écran de connexion) : `screens::primary_index(&list)`.

**La session** : une app qui gère le multi-écrans ouvre toujours ses sessions par `Session::start_with_screens(params, screens, platform)` ; le cœur décide lui-même du nombre d'écrans (`session_plan`), au départ et quand le profil change en session (`set_settings`). `params.mode` est le mode de « Cet écran », celui d'une session à un écran ; avec plusieurs écrans, le plan le remplace. Une session à un écran se fait sur « Cet écran » (`current`), avec les mêmes rappels.

1. `prepare` porte `screens` quand le plan a plusieurs écrans (ou un seul, quand les autres ont été retirés en session) ; `width`, `height` et `refresh` y décrivent l'écran principal. La réponse dit ce qui est en place (`Prepared::screens`, dans l'ordre de la demande, `None` pour un écran que la Station n'a pas pu créer ; c'est elle qui fait foi pour les modes et les positions). Sans `screens` dans la réponse (Station qui ne gère qu'un écran) ou sans écran principal, la session se fait sur l'écran principal, sans erreur.
2. Chaque écran en place est retrouvé dans la liste de Kyber par sa position et sa taille (à défaut par sa taille seule, si un seul écran libre l'a). Le cœur attend qu'ils soient tous annoncés, 6 s au plus comme pour un écran, puis démarre l'image sur ceux qui sont là ; si l'écran principal manque, sur un écran comme avant. Un écran annoncé plus tard relance l'image sur tous.
3. Une entrée vidéo par écran dans la session de Kyber, le principal en premier. La plateforme reçoit, à chaque démarrage de l'image : `on_display` (l'écran principal, comme toujours), puis `on_screens(&[StreamScreen], not_created)`, puis `input_pipeline()`. `StreamScreen { screen, display, refresh, primary }` : l'index de l'écran de l'appareil, l'écran de l'ordinateur tel que Kyber l'annonce (`id` pour les entrées, taille en pixels, position sur le bureau), sa fréquence, et s'il est principal. `not_created` : les écrans de l'appareil du plan que l'ordinateur n'a pas pu créer (`None` dans la réponse de la Station, ou jamais annoncés par Kyber) ; leur fenêtre garde le fond de la connexion avec « L'ordinateur n'a pas pu créer cet écran. ». Les paquets de chaque flux vont au gestionnaire rendu par `screen_video_handler(screen)` : un décodeur par écran. `not_created` porte aussi les écrans retirés parce que muets (ci-dessous). Une session à un écran, une Station à un écran ou le principal seul accepté : un seul écran et `not_created` vide ; les fenêtres des autres écrans ne s'ouvrent pas (ou se ferment), sans message. Le nombre d'écrans des statistiques est la longueur de la liste.
4. Débit : celui du profil, calculé sur la somme des pixels par seconde des écrans (`StreamSettings::bitrate_for_pixel_rate`), avec les mêmes plafonds ; la Station le répartit entre les écrans.
5. Image clé : `keyframe_lost` et `keyframe_recovered` comme pour un écran, depuis n'importe quel décodeur. Kyber demande l'image clé à tous les flux à la fois, et une demande avant les premières données d'un flux laisse son encodeur muet (piège déjà vécu) : le cœur ne la demande qu'une fois que chaque flux a reçu des données (chacun commence par une image clé) ; la veille redemande toutes les 300 ms et relance le flux à 1,5 s. Relancer le flux relance tous les écrans.
6. Écran muet : un flux secondaire resté sans données 4 s après le démarrage de l'image, alors que le principal en reçoit (son encodeur ne s'est pas ouvert, Kyber a quand même accepté la session), est retiré : la session se refait sans lui (connexion reprise à sa première étape) et il passe dans `not_created`. Un refus de Kyber au démarrage de l'image sur plusieurs écrans (`403`, sans dire quel écran ; `StreamingStartFailed`) : nouvel essai avec l'écran principal seul (Station refaite avec lui seul, Kyber reconnecté), une fois ; les autres fenêtres se ferment comme avec le principal seul accepté. Le principal suit les règles de reprise d'une session à un écran.
7. Mesures : `frame_displayed` (latence, première image, veille « aucune image ») pour l'écran principal seulement ; `bytes_received` pour tous.
8. Les écrans de l'appareil changent en session (branché, débranché, disposition ou recopie changée) : `Session::set_screens(screens)` ; un profil choisi en session (`set_settings`) peut aussi changer le nombre d'écrans, qui suit tout de suite. Si le plan change, la connexion reprend à sa première étape (`Status::Preparing`, puis `Connecting` et `FirstImages`, sans capsule d'adaptation) : l'image s'arrête, la Station refait les écrans, puis l'image repart, sans revenir à l'accueil. Un refus d'Admin met fin à la session avec sa raison, comme un échec de la connexion. `set_mode` (adaptation d'une session à un écran) est sans effet tant que la session a plusieurs écrans : c'est `set_screens` qui sert.
9. L'ordinateur change la taille d'un écran : `on_display` pour le principal comme avant, et `on_screens` de nouveau ; un écran disparu de la liste de Kyber relance l'image.

**Les entrées** : `InputPipeline::set_screens(Vec<ScreenTarget>)`, à appeler dans `input_pipeline()` après `on_screens` (et de nouveau quand `on_screens` revient). `ScreenTarget { screen, display_id, host_size, pointer }` : l'index de l'écran de l'appareil, l'`id` de son écran de l'ordinateur, sa taille en pixels, et la couche de pointeur de la vue de cet écran (`None` : celle donnée à `InputPipeline::new`, l'écran principal). Ensuite :

- `mouse_on(screen, x, y)` envoie une position absolue, en pixels de l'écran de l'ordinateur de cet écran, avec son `display_id` ; `mouse(x, y)` reste celle de l'écran principal ; un écran inconnu va au principal.
- Le pointeur annoncé par l'ordinateur (forme, position en pixels de son écran, visibilité) va à la couche de l'écran dont il porte l'identifiant : chaque vue ne dessine que le sien. Un pointeur qui quitte un écran y est annoncé caché. Souris Auto, une seule règle pour les trois apps : `PointerLayer::summary(couches)` (ou `InputPipeline::pointer_summary()`, couche principale et celle de chaque écran) rend un `PointerSummary { hidden, visible_for }` : caché seulement s'il l'est sur tous les écrans où le pointeur est déjà passé (un écran jamais visité, sans annonce de l'ordinateur, ne compte pas : il empêcherait le mode jeu), visible depuis le plus long de leurs délais ; à donner à `MouseModeRules::wants_relative`.
- Clavier, souris relative, molette et manettes ne changent pas.

**Pour une app Windows ou Linux**, dans l'ordre :

```rust
use kybernow_core::screens::{self, DeviceScreen, DisplaysSetting, Screens};
use kybernow_core::session::{Platform, Session, StreamScreen};
use kybernow_core::input::{InputPipeline, Options, ScreenTarget};

// 1. Les écrans de l'appareil (recopies regroupées), le principal marqué, et ce qui décide de leur nombre.
let screens = Screens {
    list: vec![DeviceScreen { x, y, width, height, pixel_width, pixel_height, refresh, primary }, /* … */],
    current,                                              // l'écran de la fenêtre de l'app
    limit_4k, custom_resolution, setting,                 // réglages de l'ordinateur
    max_screens: info.virtual_display.max_screens(),      // GET /api/stream/info
};
// Accueil et fenêtres : le même calcul que la session.
let plan = screens::session_plan(&screens, params.settings.profile, params.virtual_display, params.settings.codec);
// plan.map(|p| p.len()) : « {n} écrans, à la taille de ceux de cet appareil », sinon la ligne à un écran.
let session = Session::start_with_screens(params, screens, platform);

// 2. La plateforme (les autres méthodes comme pour un écran).
impl Platform for App {
    fn on_display(&self, d: &Display) { /* l'écran principal, comme avant */ }
    fn on_screens(&self, s: &[StreamScreen], not_created: &[usize]) { /* fenêtre de l'écran s[i].screen ↔ écran de l'ordinateur s[i].display */ }
    fn screen_video_handler(&self, screen: usize) -> Arc<dyn PacketHandler> { /* décodeur de la fenêtre de `screen` */ }
    fn input_pipeline(&self) -> Pipeline {
        let p = InputPipeline::new(Options { display_id: principal.id, host_size, clipboard, gamepads_from_app }, pointeur_principal, rappels, horloge);
        p.set_screens(ecrans.iter().map(|s| ScreenTarget {
            screen: s.screen, display_id: s.display.id,
            host_size: (s.display.width as u32, s.display.height as u32),
            pointer: Some(pointeur_de_la_fenetre(s.screen)),
        }).collect());
        p.kynput()
    }
}

// 3. En session : p.mouse_on(écran, x, y) en souris du bureau ; session.frame_displayed(…)
//    pour l'écran principal ; session.set_screens(…) quand les écrans de l'appareil changent
//    (avec les mêmes réglages) ; session.set_settings(…) suffit pour un profil changé.
```

## Plusieurs ordinateurs à la fois (`src/focus.rs`, `src/gamepads/`, `src/journal.rs`)

Une app peut tenir des sessions sur plusieurs ordinateurs, une fenêtre par ordinateur (contrat commun : [docs/plusieurs-ordinateurs.md](../../docs/plusieurs-ordinateurs.md)). Les apps Mac, Windows et Linux (interface de bureau) s'en servent. Une app à une session n'a rien à changer : sa session est active et s'entend ; l'iPhone, l'iPad, l'Apple TV, Android et les téléviseurs LG restent sur un ordinateur, sans rien appeler de neuf.

**La session** tient deux états, valables pour toute la session : la chaîne d'entrées et le moteur de son de chaque démarrage de l'image les prennent.

- `Session::set_active(bool)` (active par défaut). Pas active : rien ne part de l'appareil vers son ordinateur (clavier, souris, molette, texte, touches et axes des manettes ; branchements de manettes, relâchements et retours au repos passent toujours), les touches et clics tenus sont relâchés, ses manettes mises au repos (touches relâchées, axes au centre, gâchettes relâchées), la souris relative coupée (le réglage de l'app revient au retour), le presse-papiers en pause (rien lu sur l'appareil, rien écrit dessus ; ce que l'ordinateur annonce est ignoré, sa demande reçoit « rien »), les vibrations qu'elle avait lancées arrêtées (vibration nulle) et les suivantes ignorées, arrêt du jeu compris. De nouveau active : le contenu du presse-papiers de l'appareil est annoncé à l'ordinateur. Le passage est atomique pour les appuis : un appui (touche, clic, manette) ou un axe de l'app qui a vu la chaîne active part avant la mise au repos, jamais après, et un axe encore en attente de sa tranche de 4 ms est jeté s'il n'est pas un retour au repos. Le cœur retrouve lui-même la chaîne que la plateforme crée dans `Platform::input_pipeline` (sur le fil de session : toutes les apps la créent là) ; `InputPipeline::set_active` sert pour une chaîne seule.
- `Session::set_muted(bool)` (pas coupé par défaut) : le son est atténué en 20 ms (`AudioEngine::set_muted`), toujours décodé et tiré au même rythme : il revient sans décalage. Le cœur trouve le moteur derrière `Platform::audio_handler` quand c'est un `AudioEngine` (Windows) ou un gestionnaire qui le rend par `PacketHandler::audio_engine` ; sinon la plateforme le donne par `Session::attach_audio` (Mac : `kn_session_attach_audio`). Indépendant du volume et d'un « Couper le son » de l'app.
- Fin de session : `Platform::on_ending(raison)` arrive juste avant `Status::Ending`, avec la raison d'un échec (la même que celle de `Status::Ended`, qui attend la réponse d'Admin) ou `None` pour une fin voulue : l'app sait tout de suite que c'est un échec. `Status::Ending` reste sans champ (les apps le filtrent par son nom) ; méthode vide par défaut. Le pont C la met dans `KnStatus.error` de `KN_STATUS_ENDING`.
- `Session::set_name(nom)` : le nom de l'ordinateur au début des lignes du journal de la session (« [PC-ATELIER] image : … »), écrites par son fil, ceux qu'elle lance et le fil de ses entrées ; vide : rien, comme avant. Le registre le donne à l'inscription.

**Le registre** `kybernow_core::focus` (`focus::global()`, un par processus), seule source de « qui est active » ; les apps lui disent seulement quelle fenêtre passe au premier plan :

- `register(&Session, nom) -> Result<FocusId, Full>` : inscrit la session, quatre au plus (`MAX_SESSIONS`, au-delà `Full`) ; elle devient active, comme sa fenêtre qui s'ouvre par-dessus ; déjà inscrite : même identifiant ;
- `activate(id)` : la fenêtre de cette session passe au premier plan ;
- `set_keep_sound(id, bool)`, `keep_sound(id)` : « Garder le son », la session reste audible sans être active (coupé par défaut) ;
- `unregister(id)` : fin de la session (fenêtre fermée, « Se déconnecter », fin) ; elle passe derrière, son coupé ; si elle avait la main, celle qui l'avait juste avant la reprend (l'app corrige par `activate` si le système a mis une autre fenêtre devant) ;
- `active()`, `count()`, `ids()` (ordre d'ouverture), `next()` (« Ordinateur suivant » : la session ouverte après l'active, la première après la dernière), `name(id)`.

À chaque changement, il applique à toutes les sessions inscrites : celles qui perdent la main passent d'abord derrière (`set_active(false)`, son coupé sauf « Garder le son »), puis l'active (`set_active(true)`, son rendu) : ce que l'une relâche part avant ce que l'autre reçoit, et le presse-papiers de l'appareil n'est jamais lu pour deux. Une session libérée sans désinscription est oubliée.

**Les manettes** : un seul lecteur par app, `kybernow_core::gamepads` (`gamepads::global()`), repris de celui de l'app Linux. SDL ne s'ouvre qu'une fois par processus : deux chaînes kynput qui liraient chacune les manettes par SDL se voleraient leurs événements, et la seconde les perdrait en silence.

- **Mac et Windows** : son propre fil SDL (feature `sdl` du cœur, activée par le pont `apps/apple` sur macOS et par l'app Windows ; SDL2 liée par `build.rs`), avec une libkynput construite sans son lecteur SDL (`apps/macos/scripts/build-kyclient.sh`, `apps/windows/scripts/build.sh`). Il démarre avec la première `InputPipeline` créée avec `gamepads_from_app: false` quand libkynput n'a pas de lecteur (`InputPipeline::core_reads_gamepads`), et se ferme 5 s après l'arrêt (`stop` ou fin) de la dernière : SDL garde ouvertes les manettes qu'il ouvre (diode de joueur, mode HIDAPI des manettes Sony et Nintendo, manette réservée à l'app pour certains pilotes), comme le faisait kynput le temps de sa chaîne ; rien n'est donc ouvert hors session, et une image relancée ne referme rien. `gamepads::start_sdl()` le garde pour toute la vie de l'app (manettes ouvertes dès l'appel) : seulement pour lire les manettes hors session. Ces apps gardent `gamepads_from_app: false`, et le hook des manettes du Mac (combinaison, prise par la barre, `install_gamepad_gate`) voit ces paquets comme ceux de kynput. Fil `kybernow-manettes`, hors du fil principal comme celui de kynput (`SDL_JOYSTICK_THREAD` sous Windows, pas de gestionnaires de signaux de SDL) ; la file de SDL est vidée (`SDL_PollEvent`) toutes les 10 ms avec des manettes, 250 ms sans, comme kynput (sans sous-système vidéo, `SDL_WaitEventTimeout` tournerait 1 000 fois par seconde), et une vibration réveille le fil tout de suite ; quatre manettes au plus, numérotées dans l'ordre d'arrivée (0 à 3) ; vibrations jouées sur ce fil (-1 : 5 s, comme kynput).
- **Linux** (sa boucle SDL lit déjà manettes et fenêtres dans la même file, un second lecteur volerait ses événements) : l'app nourrit le lecteur, `gamepads::plug(id, vendor, product)`, `unplug(id)`, `button(id, PadButton, bool)`, `axis(id, PadAxis, i16)` ; les vibrations reviennent par `InputPlatform::rumble` de la session active, comme avant.
- **Routage** : chaque manette est branchée sur la chaîne d'entrées de chaque session (la Station garde sa manette virtuelle, un jeu ne la perd pas quand on change d'ordinateur), rebranchée quand une chaîne rejoint son ordinateur (`InputPipeline::network_connected`) ; appuis et axes ne vont qu'aux chaînes actives, les relâchements à toutes (un appui parti juste avant un changement de session ne reste pas tenu) ; une chaîne qui passe derrière remet elle-même ses manettes au repos, arrête les vibrations qu'elle avait lancées et ignore les suivantes. `gamepads::pads()` : les manettes présentes (identifiant, fabricant, produit, nom donné par SDL).

**Écrans** : une session ouverte pendant qu'une autre tourne prend « Cet écran », en fenêtre, quel que soit le réglage « Écrans » (deux sessions ne prennent jamais les mêmes écrans) : `screens::screens_for_extra_session(&screens)` donne les écrans à passer à `Session::start_with_screens` (`current` : l'écran de la fenêtre active, où s'ouvre la nouvelle) ; `screens::extra_session_window(&écran)` donne sa fenêtre, « centrée, aux deux tiers de cet écran, en 16:9 » ([docs/link-ui.md](../../docs/link-ui.md)) : `Mode` en pixels de l'écran (pour `SessionParams::mode`), largeur et hauteur arrondies vers le bas aux multiples de 8 (certains encodeurs et modes d'écran virtuel les préfèrent ; ce n'est pas un plafond, rien ne dépend de l'encodeur), 16:9 à 0,5 % près (la plus grande hauteur multiple de 8 dont la largeur multiple de 8 la plus proche du 16:9 tient), et le cadre dans le repère logique de l'appareil qui correspond à ce mode, recentré.

**Presse-papiers sous Windows** : la kynput.dll du client est construite sans le presse-papiers de kynput (`--cfg kybernow_app_clipboard`, correctif 0004 : sa fenêtre cachée n'existe qu'une fois par processus) ; l'app donne au cœur celui de Windows (`apps/windows/src/pasteboard.rs`, texte), un pont par chaîne, en pause hors de la session active.

**Pour une app Mac, Windows ou Linux**, dans l'ordre :

```rust
use kybernow_core::{focus, gamepads, screens};

// Mac, Windows : rien, le lecteur de manettes suit les chaînes d'entrées.
// Linux : gamepads::plug/unplug/button/axis depuis sa boucle SDL.

// « Se connecter » inactif au-delà de quatre : « Quatre ordinateurs au plus en même temps. »
let full = focus::global().count() >= focus::MAX_SESSIONS;

// Une session de plus : « Cet écran », en fenêtre, sur l'écran de la fenêtre active.
let screens = screens::screens_for_extra_session(&screens);
let window = screens::extra_session_window(&screens.list[screens.current]);
params.mode = window.mode;
let session = Session::start_with_screens(params, screens, platform);
let id = focus::global().register(&session, &nom)?;   // elle devient active

focus::global().activate(id);                         // sa fenêtre passe au premier plan
focus::global().set_keep_sound(id, garder);           // bouton « Garder le son » de la barre
let suivante = focus::global().next();                // ⌃⌥⌘O / Ctrl+Alt+Maj+O : faire passer sa fenêtre devant
focus::global().unregister(id);                       // fenêtre fermée, « Se déconnecter », fin de session
```

## KyberNow Share (`src/share.rs`, `src/session.rs`, `src/input/pipeline.rs`)

Le partage en local : un hôte en session (ou le PC lui-même) invite des spectateurs et des joueurs avec un code à six chiffres. Contrat commun : [docs/kybernow-share.md](../../docs/kybernow-share.md) (« Cœur Rust », « Échange avec Admin », qui font foi) ; textes : [docs/link-ui.md](../../docs/link-ui.md), « Partage » (catalogue `share.*` du cœur). Une session d'hôte se comporte exactement comme avant.

**Rôle de la session.** `SessionParams::role` : `SessionRole::Host` (par défaut) ou `SessionRole::Guest(Box<GuestParams { joined, capabilities }>)`, `joined` étant la réponse de `share_join` telle quelle et `capabilities` ce que l'appareil décode. `SessionParams::guest(&found, device, settings, capabilities, audio_channels)` fabrique les paramètres d'un invité d'après la Station trouvée (`console_host`, `console_port` et `console_fingerprint` sont les siens) ; `SessionParams::from_json` lit le JSON des ponts, `guest` compris (les ponts C et JNI n'ont plus leur propre copie des paramètres ; `StreamSettings::from_json` de même pour les réglages). La session s'ouvre ensuite par `Session::start` (ou `start_with_screens` : un invité n'a qu'un écran, la plateforme reçoit `on_screens` avec lui).

**Session d'invité.**

- **Pas de `prepare`.** Le format demandé à Kyber est choisi avant tout avec `capabilities` (`share::guest_format`, ci-dessous : celui de l'hôte s'il est lisible, sinon un format lisible) ; seul un appareil qui ne lit aucun format possible finit sur `ShareEnd::Unreadable` (« Cet appareil ne lit pas l'image de cet ordinateur (HEVC). ») ; format absent (l'image de l'hôte n'a pas démarré) : celui de `settings`, en 4:2:0. L'écran du partage (`joined.display`) donne le mode, sans écran virtuel.
- **Kyber** : `AuthCredentials::Jwt` avec `joined.kyber.token`, sur `joined.kyber.port`, certificat épinglé par `joined.kyber.fingerprint` ; sans empreinte, la session échoue (jamais de premier contact). Chaque signe de vie renouvelle le jeton, donné à kyclient (`update_credentials`) pour ses reconnexions.
- **L'écran** : `joined.display.id` dans la liste de Kyber (à défaut, le seul écran qu'il annonce : il ne laisse que lui à un invité), attendu 6 s ; jamais `best_display`, ni plan multi-écrans. Le signe de vie redonne l'écran (`display`) : quand l'hôte l'a refait (autre identifiant), l'invité quitte sa session de Kyber et s'y reconnecte avec le jeton de ce signe de vie, qui porte le nouvel écran (Kyber ne change l'écran d'une session qu'à une nouvelle connexion) ; l'image repart dessus (`on_mode`, `on_screens`, premières images, image), sans fin de session, et l'arrêt de l'ancienne session de Kyber n'est pas pris pour une coupure.
- **Fermé pour un invité** (`HostOnly`, chaque cas vérifié par les tests) : `prepare` (aussi après une reconnexion), signe de vie et premier plan de l'hôte (`heartbeat`, `foreground`), adaptation à un nouveau mode, session refaite, « Remettre », débit de l'image de l'hôte (`set_bitrate`, plafond de la fenêtre compris ; celui de son image à part, si : ci-dessous), repli (débit, 4:2:0), autre profil, autre écran, dernier recours (la Station n'est jamais redémarrée), `end`. Le flux de l'invité lui-même peut être relancé (aucune image, image clé perdue), sans rien changer chez l'hôte.
- **Signe de vie** : `share_beat` toutes les `joined.beat` secondes. `end: "stopped"` ou `"removed"` (la Station la donne 60 s durant, avec un jeton nul : rien n'est renouvelé), ou une Station qui ne connaît plus l'invité (404 `unknown_guest` : arrêté), finit la session avec la raison « {hôte} a arrêté le partage. » ou « {hôte} vous a retiré du partage. » ; `Platform::on_share_end(&ShareEnd, text)` arrive juste avant `on_ending` (même texte), sans « Reprendre la main », et la fin n'a pas de rapport d'écrans rendus (`report: None`). Une Station indisponible (503 `unavailable` : Kyber sans clé de jetons) ou injoignable est réessayée à chaque signe de vie ; sans réponse pendant 20 s (la Station a alors fait sortir l'invité), la session finit sur « le partage ne répond plus » (`share.lost`). Une session qui échoue côté Kyber sans que le partage l'ait dit (Admin coupe Kyber dès que l'hôte retire l'invité ou arrête le partage, avant le signe de vie suivant) interroge la Station une fois, 3 s au plus : si c'est le partage qui l'a finie, sa raison remplace celle de Kyber.
- **Départ** : `share_leave`, jamais `end`.

**Droits** (`ShareRole`, `InputRights`, `InputPipeline::set_rights`). Deux droits indépendants, que l'hôte donne ou reprend chacun sans toucher à l'autre : les manettes et le clavier et la souris. `ShareRole::Spectator` (aucun, `spectator`), `Player` (les manettes, `player`), `Kbm` (le clavier et la souris seuls, `kbm`), `PlayerKbm` (les deux, `player_kbm`) ; `pads()`, `kbm()`, et `plays()` : un droit au moins (une chaîne d'entrées, et « Joueur » dans la barre ; « Spectateur » sinon) ; `ShareRole::of(pads, kbm)`, `with_pads(bool)` et `with_kbm(bool)` donnent le rôle qu'un des deux boutons de l'hôte demande (`Console::share_guest` accepte les quatre) ; `code()` et `from_code` pour les ponts (0 spectateur, 1 manettes, 2 les deux, 3 clavier et souris seuls). Spectateur : aucune chaîne d'entrées (`Platform::input_pipeline` n'est pas appelée, Kyber ne reçoit aucune entrée, rien n'est branché au lecteur de manettes). Manettes : `gamepads` ; clavier et souris : `keyboard_mouse` (pour `Kbm`, la chaîne existe sans manettes : aucune n'est annoncée, aucune touche ni aucun axe ne part) ; jamais le presse-papiers (en pause dans la chaîne, et `clipboard` faux pour Kyber). La chaîne d'un invité ne laisse partir que ses droits, en plus de la règle « active » de plusieurs ordinateurs ; un droit retiré relâche ce qu'il tenait comme `set_active(false)` (touches et clics, souris relative coupée ; manettes au repos, vibrations arrêtées puis ignorées, nouvelle manette pas annoncée), des manettes rendues sont réannoncées. Le rôle change par le signe de vie : droits appliqués tout de suite et `Platform::on_share_role(role, Some(previous))` (avis de link-ui : « Vous pouvez jouer à la manette. », « Les manettes sont reprises. », « Vous avez le clavier et la souris. », « Le clavier et la souris sont repris. », « Vous regardez de nouveau. ») ; un spectateur qui reçoit un droit reçoit une image relancée avec sa chaîne d'entrées (Kyber ouvre les entrées au démarrage de l'image) ; un passage entre deux rôles qui ont chacun une chaîne (manettes, clavier et souris, les deux) ne relance pas l'image : le droit repris relâche seulement ce qu'il tenait, le droit donné part tout de suite ; un invité qui n'a plus aucun droit garde sa chaîne, sans droits. `on_share_role(role, None)` arrive avant la connexion. Les manettes d'un joueur gardent les identifiants de l'appareil (0 à 3 du lecteur du cœur, ceux de l'app ailleurs) : c'est la Station (Kyber, correctif 0019) qui en fait « la manette suivante de Windows », sans toucher à celles de l'hôte.

**Image d'un invité** (contrat : « L'image d'un invité » ; Kyber, correctif 0020). L'hôte passe toujours en premier : l'image d'un invité n'est jamais au-dessus de la sienne, et rien de ce que fait un invité ne la change. `ShareQuality` (`Auto`, `Host`, `P2160_60`, `P1080_60`, `P720_30`, dans l'ordre des menus (`ALL`) ; fil `auto`, `host`, `2160p60`, `1080p60`, `720p30` ; `label(lang)` : « Auto », « Comme l'hôte », « 4K · 60 Hz », « 1080p · 60 Hz », « 720p · 30 Hz » ; `code()` pour les ponts : 0 Auto, 1 comme l'hôte, 2 1080p60, 3 720p30, 4 2160p60, et `from_code`) part dans `join` (`JoinRequest::quality`, « Auto » par défaut) avec `JoinRequest::auto`, que les apps envoient quel que soit le choix (Admin l'ignore hors « Auto », le cœur le garde pour un passage à « Auto » en cours de session) : `share::auto_quality(&DeviceScreen, &DecoderCaps, Option<&ShareDisplay>) -> ShareAuto` donne la définition et la fréquence au plus celles de l'écran de l'appareil (définition native, en paysage) et de ce que son décodeur suit (`DecoderCaps { capabilities, max_width, max_height, max_fps }`, 0 : rien de connu), jamais au-dessus de l'écran partagé quand on le connaît, et les formats lus (`h264` toujours, `hevc`, `av1` ; `yuv444`). En cours de session, `Session::set_share_quality(quality)` (`POST /api/share/quality`, sur un fil d'appel) : Kyber déplace l'image de l'invité, la session n'a rien à relancer ; Admin refuse plus d'un changement par seconde (`429` `too_many`, `retry_after`) : le cœur réessaie une fois après ce délai (entre 1 et 5 s, `Console::share_quality_or_wait`, `QualityRefusal`), seulement si l'invité n'a rien choisi d'autre entre-temps (le dernier choix gagne), sans rien rendre à l'app ; avec « Auto », le cœur renvoie le `auto` mesuré à `join` (`share::join` le garde dans `ShareJoined::auto`, qui voyage avec `joined` jusqu'à la session), sans quoi Admin lirait « Auto » comme l'image de l'hôte. « Auto » est tranché par Admin d'après `auto` comparé à l'écran du partage (l'image de l'hôte si l'appareil le couvre et suit sa fréquence, sinon `1080p60` s'il affiche au moins 1920 × 1080 à 60 Hz, sinon `720p30`) : le cœur n'envoie que ce que l'appareil sait afficher et décoder ; un `join` sans `auto` garde l'image de l'hôte. L'image reçue, `ShareImage { quality, width, height, fps, codec, follows_host, reason }`, toujours un objet, vient de `join`, du signe de vie et de cette réponse : `quality` est la qualité demandée (« Auto » compris), les autres champs sont `None` (`null` d'Admin) tant que Kyber ne sait rien (relus toutes les 2 s au plus) ; `size()`, `own()` (image à part, su ; inconnu : l'image de l'hôte), `label()` (« 1080p · 60 Hz », 2160 lignes : « 4K · 60 Hz » ; `None` tant que la taille n'est pas sue), `reason: Option<Asked|Capped|Limit|Lag>`. `Platform::on_share_image(image, previous, notice)` quand elle change, `notice` étant l'avis de link-ui que donne `ShareImage::notice`, seulement sur ce qui est su : « Image allégée pour suivre. » sur une vraie baisse connue (raison `lag`, moins de pixels par seconde qu'avant, les deux tailles connues), « L'ordinateur ne peut pas faire une image de plus : vous recevez {qualité}. » (raison `limit`, taille connue, une fois par image), rien sinon. L'hôte voit `ShareGuest::image`. Le format : `share::guest_format` demande à Kyber celui de l'hôte si l'appareil le lit (en 4:2:0 sans son 4:4:4), sinon un format qu'il lit (HEVC, AV1, H.264 sinon) : Kyber fait alors une image à part, au lieu de refuser l'entrée (`join_checked` et la session ne refusent plus que si aucun format n'est possible). Images clés et débit (une image dont on ne sait pas encore si elle est à part compte comme celle de l'hôte) : un invité demande ses images clés (sur l'image de l'hôte toutes les 2 s, Kyber les espace et y voit un retard ; sur son image à part toutes les 300 ms), son flux n'est relancé qu'au bout de 5 s sans image clé, et il règle le débit de son image à part seulement (celui de cette image ; Kyber le borne), jamais celui de l'image de l'hôte. La taille des images décodées d'un invité ne change pas l'écran de l'ordinateur (repère de la souris) : seule la liste de Kyber le dit.

**Côté hôte.** `Console::share_open`, `share_state`, `share_code` (« Nouveau code »), `share_guest(id, role)`, `share_kick(id)`, `share_close` (bloquants, compte de l'appareil en session ; `ShareOpened`, `ShareState`). La liste des invités arrive avec le signe de vie (`HeartbeatReply::share`, lu sans jamais empêcher la lecture du reste) : `Platform::on_guests(Option<&ShareState>)` quand elle change (`None` : pas de partage). `Info::share` (`ShareInfo { available, enabled }`) et `ShareAvailability::of(&info)` : `Unsupported` (« Le partage demande KyberNow Station 0.8.0 ou plus récente. »), `Disabled` (« Le partage est coupé sur cet ordinateur (Admin › Appareils Link). ») ou `Available`.

**Rejoindre.** `share::join(&targets, &JoinRequest { code, name, device, app })` envoie le code à toutes ces Stations à la fois (les ordinateurs trouvés sur le réseau, comme pour l'appairage, ou celui du lien ; `Console::guest`, sans compte) et rend la première qui l'accepte : `Found { target, joined }`, `target.fingerprint` étant l'empreinte d'Admin vue pendant l'appel, que la session épingle. Sinon `ShareError::Full` (« Ce partage est complet (quatre invités au plus). »), `TooManyTries` (429), `NoShare` (« Aucun partage avec ce code sur le réseau. » : personne n'a ce code, ou personne ne répond), ou l'erreur de la seule Station essayée. `share::join_checked(.., caps)` vérifie aussi le format et repart tout de suite s'il est illisible (`ShareError::Unreadable`) ; `share::leave(&found)` pour une app qui renonce avant d'ouvrir la session. `share::parse_link` lit `kybernow://join?host&port&fp&code` et le lien du client web (`https://<adresse>:<port>/link/?join=…`, sans empreinte) ; `normalize_code` (« 123 456 » → `123456`) et `format_code` (l'inverse).

**Ponts.** C : [docs/coeur-apple.md](../../docs/coeur-apple.md) (`kn_share_*`, `kn_console_share_*`, `KN_SHARE_ROLE_*`, `kn_share_role_with_pads`, `kn_share_role_with_kbm`, `KN_SHARE_QUALITY_*`, `kn_share_quality_label`, `kn_share_auto_quality`, `kn_share_image_label`, `kn_session_set_share_quality`, `guest` dans `kn_session_start`, rappels `on_guests`, `on_share_role`, `on_share_end`, `on_share_image`). JNI : `Native.shareJoin`, `shareLeave`, `shareParseLink`, `shareNormalizeCode`, `shareFormatCode`, `shareAvailability`, `shareAvailabilityText`, `consoleShareOpen`, `consoleShareState`, `consoleShareCode`, `consoleShareGuest`, `consoleShareKick`, `consoleShareClose`, `shareRoleWithPads`, `shareRoleWithKbm`, `shareQualityLabel`, `shareAutoQuality`, `shareImageLabel`, `sessionSetShareQuality` (réponses `{"code", "value"|"error"}` ; refus de « Rejoindre » : 20 aucun partage, 21 complet, 22 trop d'essais, 23 format illisible), `guest` dans le JSON de `sessionStart`, `SessionListener.onGuests`, `onShareRole`, `onShareEnd`, `onShareImage` (méthodes par défaut vides).

## Relais : hors de chez soi (`src/relay.rs`, `src/session.rs`, `src/share.rs`, `src/console.rs`)

Partager et se connecter à son ordinateur hors de chez soi, par un relais (le relais public `share.kybernow.app`, ou celui que la Station a choisi). Contrat commun : [docs/relais.md](../../docs/relais.md) ; textes : [docs/link-ui.md](../../docs/link-ui.md), « Hors de chez vous » et « Partage ». Le tunnel est le crate commun `kybernow-tunnel` (`server/relay/tunnel`) ; kyclient n'est pas touché. Sans relais, rien ne change.

**Le tunnel** (`relay`). `RelayRoute { server, station, admin_fp }` (le relais : `share.kybernow.app`, `hôte:port`, ou `hôte:port#sha256:…` pour un relais épinglé ; une adresse sans port, c'est le 443 ; l'identifiant de la Station chez lui, 26 caractères ; l'empreinte d'Admin, **obligatoire** : jamais de premier contact par le relais). `relay::Tunnel::open(&route)` (aussi `relay::open`) rend un `Tunnel` (`RelayTunnel`) : un tunnel par (relais, Station), gardé dans un cache et fermé 30 s après son dernier usage (une poignée tenue ou des flux en cours) ; la Station est attendue 3 s chez le relais (`RelayError::StationOffline` sinon). `admin_addr()` : Admin de la Station sur `127.0.0.1:A` ; `kyber_addr(port)` : Kyber sur `127.0.0.1:L`, en TCP **et** UDP sur le même numéro, à la place du port que donne Admin (`prepare.kyber_port`, `share_join.kyber.port`) ; `stats()` (`route_info()`) : le chemin en ce moment. Le runtime tokio du tunnel est celui du cœur, deux fils (`kybernow-relais`), créé au premier usage. `RelayError` : `Unreachable` (« Le relais ne répond pas. »), `StationOffline` (« {nom} n'est pas joignable : l'ordinateur est éteint ou en veille. »), `AccessOff` (« {nom} n'est pas joignable hors de chez vous (accès coupé dans Admin). » : Admin, joint par le relais, répond 403 `remote_access_off`), `Refused`, `TooMany`, `Bad` ; `text(lang, nom)` (sans nom : « L'accès hors de chez vous est coupé dans Admin. »…), `kind()` (`unreachable`, `station_offline`, `access_off`…), `code()` pour les ponts (30 relais muet et le reste, 31 ordinateur absent du relais, 32 accès coupé ; `RelayError::from_code` refait l'erreur pour en avoir le texte avec un nom). Les apps choisissent l'état de l'accueil par l'erreur, jamais par son texte. **Adresses** : `relay::normalize(adresse)` donne la forme normale (nom en minuscules, sans schéma, sans port pour le 443 : `share.kybernow.app` ; `relais.exemple.org:9443` garde le sien ; empreinte en minuscules) ; deux relais sont le même si leurs formes sont égales. `RelayInfo::route`, `parse_link` et le cache des tunnels la prennent ; `relay::DEFAULT_RELAY` vaut `share.kybernow.app`. `relay::presence(&relais, &[ids])` : quels ordinateurs sont joignables par le relais (accueil, « Hors de chez vous »). `RelayMode` : `KYBERNOW_RELAY=force` (toujours par le relais, pour essayer à la maison) ou `off`.

**La console** : `Console::new(…).with_relay(Some(route))` fait passer tous les appels (`info`, aperçu, Station, partage) par le tunnel, Admin épinglé sur `route.admin_fp` ; un tunnel qui ne s'ouvre pas rend `ConsoleError::Relay(RelayError)`, et l'accès coupé dans Admin `ConsoleError::Relay(RelayError::AccessOff)` (plus de `ConsoleError::Http` 403 à reconnaître au texte). `Info::relay` (`RelayInfo { server, id, remote_access }`, absent sans relais réglé ou avec une Station antérieure) : l'app le garde pour chaque ordinateur ; `RelayInfo::route(admin_fp)` en fait la `RelayRoute`.

**Une session** : `SessionParams::route` : `Route::Direct` (par défaut, comme toujours), `Route::Relay(route)` ou `Route::Auto(Option<route>)` : `info` en direct en 1,5 s ; sans réponse du réseau, par le relais ; Admin qui répond, même par une erreur, garde le direct ; **une empreinte changée ne bascule jamais** vers le relais (l'erreur reste). Dans `open()` et `open_guest()`, seuls changent l'adresse et le port d'Admin (la console par le tunnel) et ceux de Kyber (`kyber_addr`) ; par le relais, l'empreinte de Kyber est exigée (jamais `enable_tofu_auto_accept`) et celle d'Admin doit être celle que l'appareil connaît (`console_fingerprint`). On reste sur le relais jusqu'à la fin de la session. JSON des ponts : `route` (`direct`, `relay`, `auto`) et `relay` (`{server, station, admin_fp}`) ; absent : direct, ou `auto` si `relay` est donné. `Platform::on_route(&RouteInfo { transport: Direct|Relay|RelayTcp, relay, rtt_client, rtt_station })` (allers-retours en ms) : au début, puis quand il change (toutes les 5 s au plus) ; puce « Par le relais », ligne « Chemin » des statistiques (`RouteTransport::label` : « Direct », « Par le relais », « Par le relais (TCP) »), `route` de la « Dernière session » (le `RouteInfo` en JSON). `Platform::on_relay_error(&RelayError, texte)` : la session finit parce que l'ordinateur n'est pas joignable hors de chez soi (`AccessOff`, `StationOffline`, `Unreachable`), juste avant `on_ending` ; `texte` est celui de link-ui avec le nom de l'ordinateur (`Session::set_name`, celui de l'inscription au focus ; pour un invité, l'ordinateur du partage), qui est aussi la raison de `Status::Ended`.

**Partager hors de chez soi** (`share`). `share::join_anywhere(&cibles, &relais, &demande, caps)` : le code part aux Stations du réseau **et en même temps** aux relais (`GET https://share.kybernow.app/v1/codes/{code}` : le relais public toujours, et ceux des ordinateurs connus, sans doublon) ; une Station du réseau qui l'accepte en 1,5 s est prise ; sinon la Station que donne un relais (sa signature vérifiée, `CodeLookup::verify`), rejointe **de bout en bout** par le tunnel, Admin épinglé sur l'empreinte attestée. L'issue : `Joining::Joined(Found)` (l'invité entre) ou `Joining::Pending(PendingJoin { route, guest, secret, expires, auto })` (« En attente de l'accord de l'hôte… ») ; `share::wait(&pending, caps)` (appel tenu 25 s : `Ok(None)` toujours en attente, `Ok(Some(found))` accepté, `ShareError::Refused` « L'hôte a refusé. », `ShareError::Expired` « L'hôte n'a pas répondu. », `ShareError::Stopped` « Ce partage est arrêté. » quand l'hôte arrête le partage pendant l'attente (`{"error":"stopped"}`), `NoShare`) ; `share::cancel(&pending)` (« Annuler »). `ShareError::PendingFull` : trois demandes attendent déjà. Un invité venu par le relais y reste : la route voyage avec `joined` (`ShareJoined::route`, champ local) jusqu'à la session, et `share::leave` passe aussi par le relais. Lien : `parse_link` lit `relay` (sous sa forme normale) et `sid` ; `JoinLink::relay_route()` (de bout en bout, Admin épinglé sur `fp`) ; `share::join_link(&lien, &demande, caps)` : la Station du réseau d'abord (1,5 s), puis le relais.

**Côté hôte, hors de chez soi** (`share`, `console`). La vue du partage (`ShareState`) porte `relay` (`ShareRelay { state }` : `Joined` ou `Unreachable` ; `None` sans relais réglé ou avec une Station antérieure ; `relay_joined()`) et `web_local` (l'adresse du client web sur le réseau, alors que `web` est celle du relais quand il tient le code) ; chaque invité (`ShareGuest`) porte `pending` (une demande venue par le relais que l'hôte n'a pas encore acceptée : spectatrice, sans place) et `via` (`ShareVia::Lan` ou `Relay`, « hors de chez vous »). `ShareState::requests()` donne les demandes (la liste « Demandes », la pastille « 1 demande »), `ShareState::seated()` les invités qui ont une place (la liste « Invités », la pastille « 2 invités », la limite de quatre) ; un champ absent ou inconnu se lit sans demande, sur le réseau, relais injoignable. `Console::share_accept(id)` et `share_refuse(id)` (`POST /api/share/guest/{id}/accept|refuse`, compte de l'appareil en session, bloquants) rendent le partage à jour : accepter fait entrer la demande comme spectatrice (Admin refuse en 409 `full` si les quatre places sont prises), refuser l'écarte (son appareil ne redemande pas avant 10 minutes). La liste arrive toujours avec le signe de vie (`Platform::on_guests`), demandes comprises.

## Prêt de l'ordinateur (`src/lend.rs`, `src/session.rs`, `src/share.rs`, `src/console.rs`)

Un ami emprunte le PC de l'hôte, que la Station passe en mode console. Contrat : [docs/pret.md](../../docs/pret.md) ; textes : [docs/link-ui.md](../../docs/link-ui.md), « Prêt de l'ordinateur ». Hors de chez soi, les mêmes appels passent par le relais (ci-dessus).

**L'ami.**
- `lend::status(&cible, route, identifiant, mot_de_passe)` : la carte « Ordinateur de {hôte} » (`LendStatus { state, host, computer, slot, mine }` ; `mine` : le prêt en cours est le sien, il peut y revenir). `LendAvailability::label` donne « Disponible », « Occupé », « Prêté à quelqu'un d'autre », « Verrouillé », « Prêt coupé ».
- `lend::borrow(&cible, route, &BorrowRequest { credentials: LendCredentials::Code { code } | Account { login, password }, name, device, app, screen, codecs })` rend `Borrowing::Ready(Loan { target, borrowed })` ou `Borrowing::Pending(PendingBorrow)` (« En attente de {hôte}… »). L'appel est bloquant : la Station prépare le mode console en 40 s au plus, le cœur attend 50 s (`lend::BORROW_WAIT`).
- `lend::wait(&en_attente)` : appel tenu 30 s, plus la préparation une fois l'hôte d'accord (80 s au plus, `lend::WAIT_WAIT`) ; `Ok(None)` toujours en attente, `Ok(Some(prêt))` accepté ; une demande que la Station ne connaît plus (`404 unknown`) : `Expired`. `lend::cancel` : « Annuler ». `lend::leave(&prêt)` : « Rendre l'ordinateur » hors d'une session.
- Le chemin : sans route, sur le réseau ; avec une route (lien d'invitation avec `relay` et `sid`), sur le réseau si Admin y répond en 1,5 s, sinon par le relais. Une Station venue par le relais (`port` 0) passe toujours par lui.
- Refus (`LendError`, `text(lang, hôte)`, `kind()`, `code()` 40 à 48 pour les ponts) : `BadCredentials`, `NoCode`, `Lent`, `Locked`, `Off`, `TooMany`, `Refused`, `Expired`, `Unsupported` (Station avant 0.9.0), `Other`.
- `lend::parse_invite` lit `kybernow://borrow?host&port&fp&login[&relay&sid][&name]` et `https://…/link/?borrow=<identifiant>[&name=…]` (`Invite::target()`, `relay_route()` ; `Invite.name` : le prénom de l'hôte, pour « {hôte} vous prête son ordinateur. » avant le premier statut).

**Rejoindre avec un code.** `share::join`, `join_checked`, `join_anywhere` et `join_link` rendent `ShareError::Lend(LendCode { code, target, route })` quand la Station répond `404 {"error":"no_share","lend":true}`. L'app emprunte alors avec `lend::borrow(&c.target, c.route.as_ref(), …Code { code })`. `share::Joining` ne change pas.

**La session d'emprunt** : `SessionParams::borrower(&prêt, appareil, réglages, voies)`, `SessionRole::Borrower(BorrowerParams { borrowed })`, JSON des ponts `borrower` (`{"borrowed": …}`).
- Pas de `prepare` : l'écran virtuel est déjà fait ; l'image vient de l'écran que donne la Station.
- Kyber avec le jeton renouvelé par `POST /api/lend/beat` (toutes les `beat` secondes).
- Clavier, souris et manettes (`ShareRole::PlayerKbm.rights()`), jamais le presse-papiers.
- Comme un invité : ni signe de vie d'hôte, ni `foreground`, ni changement d'écran ou de profil, ni redémarrage de la Station, ni `end`.
- Reconnexion de Kyber par kyclient. Une Station injoignable 20 s finit la session (« l'ordinateur prêté ne répond plus ») ; l'ami revient pendant 15 min par `borrow` (`lend::COME_BACK`).
- Préavis : `Platform::on_lend_notice(&LendNotice { reason, at }, texte)`, une fois par préavis.
- Fin : `Platform::on_lend_end(LendEnd, texte)` juste avant `on_ending`, avec le texte de la carte de fin :
  - `TakenBack` « {hôte} a repris l'ordinateur. » ;
  - `TimeUp` « Le prêt est terminé. » ;
  - `SlotEnd` « Votre créneau est terminé. » ;
  - `Stopped` « Le prêt s'est arrêté. » (agent de console perdu, ou Station qui ne connaît plus le prêt : 401, 403, 404, 410) ;
  - `Left` « Vous avez rendu l'ordinateur. » : rendu depuis le lanceur, une fin voulue, sans erreur.
- `Session::give_back()` : « Rendre l'ordinateur » (`leave`, puis fin sans erreur). `Session::stop()` ne rend rien.

**L'hôte.**
- `Console::lend_state`, `lend_code(durée, LendSteam)`, `lend_cancel_code`, `lend_answer(id, accepter, steam)`, `lend_take_back(tout_de_suite)` rendent la vue du prêt : `LendView { available, enabled, computer, host, state, borrower, notice, requests, code }`. Le code de séance (`LendCodeView`) porte `relay`, comme la vue du partage (`ShareRelay` : `connecting`, `joined`, `unreachable`), avec `relay_joined()` et `relay_connecting()`. Chaque demande (`LendRequest`) porte aussi `steam` (le compte proposé) et `slot` (demande d'un créneau : prêtée dans 2 min sans réponse).
- La même vue arrive avec le signe de vie de l'hôte : `HeartbeatReply::lend`, puis `Platform::on_lend(Option<&LendView>)` quand elle change.
- `Info::lend` : `LendInfo { available, enabled }`, absent pour une Station antérieure.

## Module d'entrées partagé (`src/input/`)

Les entrées de toutes les apps (Mac, Apple TV, iPhone et iPad par `apps/apple` et `InputCore.swift` ; Android par JNI ; Windows, Linux et webOS directement), au-dessus de la chaîne kynput de Kyber (`kynput_rs`, `kynput_sys`) : chaîne et file de secours, clavier, combinaison de la manette, tout relâcher, pointeur de l'ordinateur, presse-papiers (voir « Entrées » dans [apps/macos/README.md](../macos/README.md)).

| `packet.rs` | `OwnedPacket` : un paquet kynput dont on tient la référence (libérée à la fin, clonée par essai d'envoi, cédée à kynput) ; `PacketSink` : l'envoi vers la chaîne, `KynputSink` (le puits d'entrée d'une chaîne kynput) |

| `keymap.rs` | Usages HID → scancodes (`kynput_keycode_usb_to_kyber`), « ⌘ envoyée comme Ctrl », échange des touches `@#` et `<>` des claviers Apple ISO (la disposition n'est demandée que pour ces deux touches), Verr. maj. et Verr. num. reconnues comme des bascules, réglage ISO des claviers Apple ou inconnus |

**Minuteries.** Aucun module ne crée de fil ni de file : chacun expose `poll()` et `next_deadline()`, et `InputPipeline::poll` les appelle tous (réessais, axes, combinaison, presse-papiers, paquets reçus). La plateforme appelle `poll()` au plus tard à l'échéance depuis la file qu'elle veut, ou laisse `InputPipeline::spawn_driver` tenir un fil (`kybernow-entrees`) qui dort jusqu'à l'échéance ou au réveil (`wake()`, tiré par tout ce qui crée une attente). Les tests avancent une `ManualClock` et appellent `poll()` eux-mêmes.

**Fils.** Toutes les méthodes sont appelables de tout fil (état sous verrou). Les rappels de kynput arrivent sur son fil réseau : le pointeur va à `PointerLayer`, qui prévient la vue hors de son verrou ; les vibrations à `InputPlatform::rumble` ; les paquets du presse-papiers sont copiés et traités par `poll()`, hors du verrou du routeur (la réponse y réentrerait).

### Ce que la plateforme fournit

```rust
// Horloge monotone (CLOCK_UPTIME_RAW, QueryPerformanceCounter…).
pub trait Clock: Send + Sync {
    fn now(&self) -> Duration;
}

// Presse-papiers texte (NSPasteboard, UIPasteboard, Android, Linux ; None sur tvOS et webOS ; celui de kynput sous Windows).
pub trait Pasteboard: Send + Sync {
    fn change_count(&self) -> u64;
    fn text(&self) -> Option<String>;
    fn set_text(&self, text: &str);
}

// Rappels vers l'interface (toutes les méthodes ont un défaut vide).
pub trait InputPlatform: Send + Sync {
    fn rumble(&self, rumble: GamepadRumble) {}  // fil réseau de kynput
    fn combo_formed(&self, pad: PadId) {}        // fil qui appelle poll()
    fn connected(&self) {}                       // fil de network_connected()
    fn navigate(&self, key: PadKey) {}           // fil de kynput, sous le verrou du routeur
}

// Envoi substitué (tests, bancs d'essai).
pub trait PacketSink: Send + Sync {
    fn consume(&self, packet: OwnedPacket) -> bool;
}
```

Et, en dehors des traits : la **capture des événements** (AppKit, GameController, Win32, Raw Input, SDL, Android) traduite en appels à `InputPipeline` (`key`, `mouse`, `mouse_move`, `mouse_button`, `wheel`, `type_text`, `gamepad_*`, `release_all`, `flush_keys`) ; l'**usage HID** de chaque touche et la **disposition ISO** (`keymap::scancode(hid, command_as_control, || iso)`) ; le **dessin** du pointeur sur le fil principal depuis `PointerLayer::set_on_changed` ; la **règle du mode de souris** (`MouseModeRules { needs_hidden_pointer }`, `true` sur Mac, Windows et Linux, `false` sur Apple TV, iPhone, iPad et Android) ; les manettes SDL du Mac et de Windows sont lues par le lecteur unique du cœur (`crate::gamepads`, avec une libkynput sans le sien ; par kynput sinon) ; sur Mac, le hook du routeur (`install_gamepad_gate`) les filtre et rend les touches de navigation par `InputPlatform::navigate`.

Création : `InputPipeline::new(Options { display_id, host_size, clipboard, gamepads_from_app }, pointer, platform, clock)` rend un `Arc` ; `kynput()` donne la chaîne à `session::Platform::input_pipeline` ; `start_clipboard()` une fois le réseau relié ; `stop()` en fin de session (FlushKeys direct, total des pertes au journal), `shutdown()` pour arrêter les gestionnaires de kynput.

## Moteur de son (`src/audio/`)

Le son de toutes les apps, sans la sortie : la plateforme (Core Audio, WASAPI, AAudio, SDL) tire le son du moteur depuis son fil temps réel. Mac, Apple TV, iPhone et iPad y passent par `kn_audio_*` (`AudioPlayerCore.swift`), Windows directement (`apps/windows/src/audio.rs`), Android par AAudio (`apps/android/jni/src/audio.rs`), Linux et webOS par SDL (`apps/linux/src/device/media.rs`, `apps/webos/src/device/media.rs` ; en 5.1, webOS donne le son au lecteur du téléviseur).

| Module | Ce qu'il tient |
|---|---|
| `opus.rs` | libopus multistream : `Decoder` (stéréo, 5.1, 7.1 depuis l'en-tête `OpusHead` de `media.rs`), trame de masquage ; un encodeur pour les tests |
| `ring.rs` | Anneau d'échantillons à un producteur (fil réseau) et un consommateur (fil temps réel), sans verrou |
| `mix.rs` | Mixage descendant (G + 0,7 C + 0,7 surround G et arrière G, idem à droite, LFE ignoré ; 7.1 → 5.1 ; mono = moyenne) et `OutputOrder` (Opus, Windows, Core Audio 5.1 A / 7.1 C, ou sur mesure) |
| `engine.rs` | `AudioEngine` : `configure` / `decode` / `conceal` (ou `PacketHandler::packet`) depuis le fil réseau de Kyber, `fill(&mut [f32], frames)` depuis le fil temps réel ; tampon adaptatif ; `AudioStats` une fois par seconde ; son coupé ou rendu en 20 ms (`set_muted`, plusieurs ordinateurs) |

Tampon : marge de 8 ms au départ, qui grandit de 5 ms après un tampon vide (60 ms au plus) et redescend d'1 ms toutes les 2 s sans trou (4 ms au moins) ; premier départ à la marge plus un paquet, reprise dès que la marge est là ; un tampon vide est comblé par une trame de masquage d'Opus (silence si le décodeur est occupé par le fil réseau à cet instant) ; dérive rattrapée par un échantillon sauté ou doublé sur 256 (sur 128 au-delà de 6 ms d'écart) jusqu'à ce que le plus bas niveau de la seconde retrouve la marge ; coupe sèche seulement au-delà de 10 ms d'avance. Un tampon plein (sortie arrêtée depuis une seconde) jette ce qui arrive ; la coupe sèche rattrape l'écart au redémarrage.

`fill` ne prend aucun verrou bloquant : l'anneau est sans verrou, le décodeur (trame de masquage) et les mesures sont pris par essai, et un essai manqué donne du silence pour cette demande. Le nombre de voies de la sortie est `out.len() / frames` : la plateforme le change en changeant la taille de son tampon (AirPods branchés sur un flux 5.1), et donne sa latence par `set_output_latency_ms` (tampon de la carte son plus ce qu'elle annonce) pour l'écart son-image des mesures (`take_stats`).

### Ce que la plateforme fournit

- La sortie elle-même : son fil, le nombre de voies qu'elle accepte (ou mixe), son ordre des voies (`AudioEngine::with_order`), sa latence ; sa recréation quand la sortie du système change.
- L'horloge (`Clock`, celle du module d'entrées).
- libopus à l'édition de liens : `build.rs` la demande à pkg-config (`PKG_CONFIG_PATH` vers le rootfs de Kyber sur le Mac) et se contente d'un avertissement sinon (l'app Windows la lie en statique, `apps/windows/build.rs`).

## Tester

Sur le Mac, avec le SDK Kyber compilé pour macOS (`third_party/kyber-desktop/rootfs-arm64-macos`, produit par les scripts de l'app Mac) :

```bash
cd apps && PKG_CONFIG_PATH=$PWD/../third_party/kyber-desktop/rootfs-arm64-macos/lib/pkgconfig LIBCLANG_PATH=/Library/Developer/CommandLineTools/usr/lib cargo test -p kybernow-core
```

Les tests des entrées couvrent la table du clavier, ISO, Verr. maj. ; combinaison brève, tenue, relâchement complet, réglage coupé ; file de secours : accepté, refusé deux fois puis parti dans l'ordre, refusé sans fin, arrêt ; filtrage et regroupement des axes, remise au repos, tout relâcher, texte, pointeur dédoublonné, presse-papiers dans les deux sens ; ceux du son, un la de 440 Hz encodé en Opus, stéréo et 5.1 au rythme réel avec ± 8 ms d'à-coups et une perte sur 97, paquets de 10 ms, dérive de 0,2 % dans les deux sens, sortie arrêtée 200 ms puis coupe sèche, mixage et ordre des voies. Ils avancent une `ManualClock` à la main : ils ne durent qu'une seconde. `cargo test -p kybernow-core input` ou `… audio` pour une moitié. Ceux de la session (`… session`) couvrent le dernier recours avec une fausse console : quand il se déclenche et quand il ne se déclenche pas, une seule fois, refus d'Admin (toujours sans `force`), retour de la Station, délai dépassé, annulation pendant l'attente, et les textes. Ceux du multi-écrans (`… screens`, `… session`, `… console`, `… input`) : la disposition de l'auteur (XG32UQ 4K principal au centre, Studio Display 5K à droite, MacBook Pro à gauche et plus bas), avec « Au plus 4K » et en H.264, des écrans empilés, des échelles mélangées, un écran isolé, un écran qui glisserait sur un autre, quatre écrans au plus, et 300 dispositions tirées au hasard que Windows doit accepter (principal en (0, 0), aucun chevauchement, tous reliés) ; le JSON de `prepare` dans les deux sens ; les écrans retrouvés dans la liste de Kyber ; le réglage et le nombre d'écrans (profils, définition sur mesure, Station antérieure, `max_screens`) ; un écran retiré (plan refait, écran muet, « non créé ») ; les premières données notées par flux ; les positions et le pointeur routés par écran. Ceux de plusieurs ordinateurs (`… focus`, `… gamepads`, `… session`, `… clipboard`, `… audio`, `… screens`, `… journal`), avec des chaînes d'entrées et des moteurs de son sans réseau : inscription, activation, « Garder le son », quatre au plus, désinscription (la précédente reprend la main), session disparue oubliée ; manettes branchées sur toutes les sessions, touches et axes à l'active seule, remises au repos en changeant d'ordinateur, rebranchées quand une chaîne rejoint son ordinateur, vibrations de l'active seule, arrêtées quand elle passe derrière (arrêt du jeu ignoré ensuite), relâchements transmis à toutes les sessions ; aucun appui ni axe en mouvement après le passage derrière (un fil qui appuie sans arrêt pendant le passage), axe en attente jeté ; la raison d'un échec avant la fin en cours ; clavier coupé en arrière-plan et touches relâchées ; l'état de la session repris par la chaîne et le moteur de son d'une image relancée ; presse-papiers en pause puis contenu de l'appareil annoncé ; son coupé en fondu de 20 ms, tiré au même rythme, rendu ; une session de plus sur « Cet écran » et sa fenêtre 16:9 ; le nom de l'ordinateur dans le journal. Ceux de KyberNow Share (`… share`, `… session`, `… input`, `… console`), sans réseau (une Station sur un port fermé de la machine) : chaque appel qui change l'ordinateur fermé pour un invité, appelé directement ou demandé par l'app (`prepare`, signes de vie et premier plan de l'hôte, adaptation, session refaite, « Remettre », débit, image clé, repli, dernier recours, profil, écran, `end`), et permis pour un hôte ; l'écran du partage dans la liste de Kyber (attendu, puis la raison) ; les droits selon le rôle (deux droits indépendants : chacun donné ou repris sans toucher à ce que l'autre tient, le clavier et la souris seuls sans manettes, aucune relance entre deux rôles qui ont une chaîne ; spectateur sans chaîne d'entrées, joueur devenu tel pendant l'image : image relancée ; clavier et souris donnés puis repris : touches et clics relâchés, souris relative coupée ; redevenu spectateur : manettes au repos, nouvelle manette pas annoncée, réannoncées quand elles sont rendues ; jamais le presse-papiers ; manettes retenues dans le portier de kynput) ; les fins (arrêté, retiré sans jeton, Station qui ne connaît plus l'invité, Kyber coupé avant le signe de vie) ; les réponses du signe de vie (503 et réseau réessayés jusqu'aux 20 s) ; un nouvel écran du partage (reconnexion à Kyber, arrêt de l'ancienne session ignoré, avec un rôle changé en même temps) avec leur texte avant la fin en cours et sans rapport ; le format choisi avant Kyber (celui de l'hôte, en 4:2:0 sans son 4:4:4, un format lisible sinon : jamais de refus), et l'empreinte de Kyber exigée ; la qualité de l'image (noms, libellés, 4K et ordre des menus, changement trop rapproché réessayé une fois si rien de plus récent, « Auto » d'après l'écran, le décodeur et l'image de l'hôte, `join`), l'image reçue (lue partout, champs `null` tant que Kyber ne sait rien, avis seulement sur une baisse connue et sur la limite, débit et images clés sur l'image à part ou celle de l'hôte, souris inchangée par une image plus petite, qualité changée sans relance) ; la liste des invités de l'hôte à chaque changement seulement, et le signe de vie lu même avec un `share` illisible ; les JSON de `join`, du signe de vie, de la liste et des paramètres des ponts (hôte et invité) ; les liens, les codes, les formats lisibles, la Station du code trouvée parmi plusieurs (complète, trop d'essais, injoignable). Ceux du relais (`… relay`, `… share`, `… session`, `… console`) : sur la boucle locale, un faux relais (QUIC `kn-ctl/1` et `kn-media/1`, HTTPS `GET /v1/codes/{code}` sur le même port, relais épinglé par son certificat d'essai) et un faux Admin (TLS) avec le vrai tunnel : tunnel partagé par (relais, Station), points d'écoute de Kyber en TCP et UDP sur le même numéro, `info` par la console épinglée, une autre empreinte d'Admin refusée, le code trouvé et sa signature vérifiée, relais muet ; le partage complet par le relais (demande en attente, attente, accord, route gardée dans `joined`, annulation et départ par le relais) ; et sans réseau : le choix du chemin (direct, `Auto` avec ou sans réponse, empreinte changée, `force`, `off`), l'empreinte obligatoire, la recherche parallèle (réseau en 1,5 s, relais ensuite, Station absente, code inconnu, relais muet, complet, trop d'essais), le lien avec `relay` et `sid`, les réponses de `join` et `wait`, le JSON de `route`. Ceux du prêt de l'ordinateur (`… lend`, `… session`, `… share`) : par le faux relais et le faux Admin, le code de « Rejoindre » qui est un code de prêt, l'emprunt par ce code par le même chemin, l'attente puis l'accord, la session d'emprunt par le relais, le signe de vie, l'annulation et l'ordinateur rendu, la carte d'un compte d'ami (mot de passe refusé, puis disponible), une Station sans prêt ; et sans réseau : chaque appel qui change l'ordinateur fermé pour un emprunt, les droits (clavier, souris, manettes, pas de presse-papiers), l'écran du prêt dans la liste de Kyber, le jeton renouvelé, le préavis dit une fois, les fins avec leur texte avant la raison, l'ordinateur rendu seulement par « Rendre l'ordinateur », la vue du prêt de l'hôte à chaque changement seulement, les JSON (statut, demande, réponses, signe de vie, vue de l'hôte, paramètres des ponts), les refus et leurs codes, les liens d'invitation, le code de prêt trouvé parmi plusieurs Stations. Le fil SDL lui-même n'est pas testé ici (`cargo check -p kybernow-core --features sdl`) : il se vérifie avec une manette, dans l'app.
