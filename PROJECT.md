# KyberNow — cadrage

[English](PROJECT.en.md) · Français

Serveur Windows (toute carte graphique : NVIDIA, AMD, Intel, eGPU compris ; sinon le processeur) clé en main + GUI web d'administration, et clients natifs macOS, tvOS, iOS/iPadOS et Windows « à la Moonlight », et client web, construits sur [Kyber](https://kyber.tech) (SDK de streaming basse latence de l'équipe VLC, Rust + FFmpeg + VLC + QUIC). Trois produits sous la marque KyberNow :

- **KyberNow Station** : le serveur installé sur l'ordinateur Windows qui diffuse son image (installateur, services, icône de la zone de notification, mises à jour) ;
- **KyberNow Admin** : l'administration de la Station dans le navigateur (service `kyber-admin` et son interface Svelte) ;
- **KyberNow Link** : les apps qui affichent l'image (Mac, Apple TV, iPhone et iPad, Windows) et le client web `/ecran` servi par Admin.

## Ce que Kyber fournit (v0.29.0, 2026-10-09)

- Serveur Windows 10/11 : service Windows (`kyservice` → `kycontroller`, `kyavserver`, `kynputserver`), icône de zone de notification, NVENC recommandé, port unique `8080` TCP+UDP.
- Config unique `kyber_config.toml` (encodeur, débit mini, port, TLS, JWT/OIDC, presse-papiers, manette, écrans virtuels « Kidd »). La plupart des changements nécessitent un redémarrage. Surcharge possible via `KYBER_CONFIG`.
- Manettes : pilote ViGEmBus requis côté serveur.
- Client web servi par le contrôleur sur `/webclient/`.
- SDK client : cœur Rust, bindings C (`libclient`, `libkynput`) via cbindgen ; rendu via VLC (fork). App `kyber-ios` (iOS/tvOS) **non publique**.
- Pas de traversée de NAT → LAN / VPN.
- Sources : https://gitlab.com/kyber (docs : `kyber/kyber`, apps : `kyber/apps/*`, cœur : `kyber/core/*`).

## Architecture

```
kybernow/
├── server/             # KyberNow Station
│   ├── admin/          # kyber-admin (KyberNow Admin) : service Windows en Rust (axum)
│   ├── web/            # SPA Svelte d'Admin et client web /ecran, compilés et embarqués dans admin
│   ├── tray/           # icône de la zone de notification
│   ├── installer/      # installateur (Rust + WebView2 + Svelte) : Kyber + SudoVDA + ViGEmBus + kyber-admin + pare-feu + alimentation
│   └── kyber-patches/  # correctifs de Kyber, surcouche posée par l'installateur
└── apps/               # KyberNow Link
    ├── core/           # cœur client en Rust (kybernow-core) : session, `console` (dialogue avec Admin), entrées, son, latence
    ├── apple/          # pont C du cœur pour les apps Apple (libkybernow)
    ├── macos/          # app macOS (SwiftUI ; KyberKit, partagé avec tvOS et iOS)
    ├── tvos/           # app Apple TV
    ├── ios/            # app iPhone et iPad
    ├── android/        # app Android et Android TV (Kotlin + Compose ; pont JNI du cœur dans android/jni)
    └── windows/        # app Windows (Tauri + Svelte, Direct3D 11) et son installateur
```

### KyberNow Admin (kyber-admin, Windows)
- Tourne en service Windows, HTTPS sur un port dédié, accès protégé par mot de passe.
- **Config** : lecture/écriture de `kyber_config.toml` en préservant les commentaires (`toml_edit`), validation par schéma, application avec redémarrage contrôlé du service Kyber.
- **Service** : start / stop / restart / état du service Kyber.
- **Supervision** : carte graphique et pilote (`Win32_VideoController`), charge de la carte et de son encodeur, flux en cours (compteurs « GPU Engine » de Windows, pour NVIDIA, AMD et Intel) ; en plus pour NVIDIA, par NVML : sessions NVENC, images par seconde, latence, alimentation, température. Session active, logs en direct.
- **Appairage** : page « Appareils Link » d'Admin : QR code et lien `kybernow://adresse:port?name=…&fp=sha256:…` (adresse, port d'Admin, empreinte de son certificat ; aucun secret). L'app lit le QR code à la caméra ou le lien collé (ou ouvert : schéma `kybernow://`). L'empreinte vue est comparée à celle du lien ou de l'annonce ; par simple adresse, l'utilisateur la compare à celle d'Admin (4 premiers groupes). Puis compte d'Admin, vérifié et gardé dans le Trousseau ; certificat épinglé. **Par code** : l'appareil envoie un code à 6 chiffres à Admin sans compte, on l'accepte dans Appareils Link ou le panneau de l'icône ; il reçoit un compte Kyber à lui (mot de passe aléatoire), accepté par Admin et Kyber, révocable sur sa carte (« Retirer l'accès »), sans changement côté app. Voir [server/README.md](server/README.md).
- **Découverte** : annonce Bonjour/mDNS `_kybernow._tcp` d'Admin (TXT `v`, `name`, `fp`), règle de pare-feu UDP 5353 pour kyber-admin.
- **Accueil des apps** : `GET /api/stream/info` donne le système de l'ordinateur (« Windows 11 Pro 24H2 », pensé pour une Station sur d'autres systèmes), `GET /api/stream/preview` un aperçu JPEG de l'écran principal (capture GDI par l'agent dans la session de l'utilisateur, 10 s de cache, jamais pendant une session), fond de l'accueil quand l'app n'a pas d'image de la dernière session.
- **Profils** : « Jeu » (faible latence, manette, haut fps) / « Bureau » (4:4:4, presse-papiers, multi-écrans).
- **Client web** (`/ecran/`) : servi par Admin, avec sa session. Admin signe un jeton JWT pour Kyber (clé posée à l'installation), relaie les appels HTTPS et WebSocket du moteur `kyclient_wasm` à kycontroller (qui refuse les autres origines) et sert les fichiers du moteur depuis le `/webclient/` installé ; l'image arrive directement de Kyber en WebTransport. Détails dans [server/README.md](server/README.md). **Reste à valider sur l'ordinateur** : la session de bout en bout (image, son, clavier, souris, manette, presse-papiers), la reprise de main d'un autre appareil, le tactile et le clavier des téléphones et tablettes (les gestes sont traduits en événements de souris et de clavier envoyés au moteur).

### Écran virtuel (session de stream)
- **Début de session** : le client annonce sa résolution et sa fréquence à kyber-admin (nos apps) ou on prend le mode par défaut ; kyber-admin crée l'écran virtuel SudoVDA à ce mode, mémorise la disposition des écrans, n'active que l'écran virtuel, et la capture Kyber le suit.
- **Fin de session** : écran virtuel retiré, disposition d'origine restaurée.
- **Filet de sécurité** : le pilote retire l'écran s'il ne reçoit plus de signal de vie (3 s) ; kyber-admin restaure la disposition à son démarrage et quand plus aucun flux n'est encodé (toute carte graphique) ; raccourci clavier d'urgence.
- ✅ **Vérifié le 2026-10-19** sur l'ordinateur (RTX 3080 Ti, 2 écrans 4K) : écran virtuel 3840 × 2160 à 160 Hz créé avant la connexion, écrans physiques éteints puis restaurés, stream reçu à 152 i/s, 8,3 ms de latence médiane.
- **Piège** : l'énumérateur d'écrans de Kyber voit l'ancienne disposition pendant ~50 ms ; `prepare` attend que Windows n'affiche plus que l'écran virtuel, puis 1,5 s, avant de répondre, et le cœur des apps attend que Kyber annonce l'écran virtuel avant de le choisir.
- **Piège** : le chien de garde de SudoVDA (3 s) est armé dès la création de l'écran. Le signal de vie part donc d'un fil dédié dès `add`, pas une fois la session active : sinon l'écran disparaît pendant la mise en place (écran blanc côté client, échec d'initialisation de l'encodeur côté serveur).
- **Reste à valider** : le mode « Pour toute connexion » (écran créé en cours de flux), et la reprise de main par un 2e appareil (déconnexion du 1er).
- **Architecture** : le service pilote SudoVDA (IOCTL, signal de vie) ; un agent éphémère `kyber-admin display-agent`, lancé avec le jeton SYSTEM dans la session console, change la disposition (API CCD).
- **Concession de sécurité** : SudoVDA est auto-signé, son certificat est ajouté aux autorités racines de l'ordinateur.

### Qualité d'image : 4:4:4, HDR, VRR (Kyber 0.29)
- **4:4:4** ✅ vérifié le 2026-10-19 (HEVC, 3840 × 2160 à 160 Hz, client `--444`). Coût par rapport au 4:2:0 : encodage NVENC ~9 ms en médiane (p95 46 ms), décodage ~6,6 ms, latence totale ~18 ms en médiane. Proposé dans le profil « Bureau » (texte net), pas dans le profil « Jeu ».
- **HDR** ❌ impossible avec Kyber 0.29 : la capture (DXGI Desktop Duplication) est en BGRA 8 bits. Garder le HDR Windows désactivé sur l'écran virtuel.
- **Son multicanal et HD** (correctif `server/kyber-patches/0001`) : le moteur txproto capture la sortie Windows avec tous ses canaux ; Kyber fixe le débit Opus à 128 kbit/s, le correctif le fait suivre le nombre de canaux. Réglage `[kyavserver] audio_quality` : `standard` (128 kbit/s), `hd` (défaut : 256 kbit/s en stéréo, 576 en 5.1, 768 en 7.1), `studio` (maximum d'Opus) ; `audio_bitrate` pour une valeur exacte. Le moteur libavconv garde aussi le 5.1 et le 7.1 (0008) ; `audio_layout = "stereo"` l'en empêche, pour le client web qui ne lit que la stéréo. L'app propose Auto, Stéréo, 5.1, 7.1 ou Aucun ; Auto suit la sortie audio du Mac.
- **VRR** : côté serveur, Kyber envoie une image quand l'écran change (débit d'images suivant le contenu). Côté client, chaque image part à l'écran dès qu'elle est décodée, la plus récente remplace les autres : sur un écran ProMotion / Adaptive-Sync, l'écran se cale sur l'arrivée des images. Synchro verticale désactivable (latence minimale, déchirure possible). Pas de VRR sur Apple TV.
- **Décodage par l'app** : correctif `apps/macos/kyber-patches/0001` sur libkyclient (`kyclient_video_player_config_set_packet_sink`) : les paquets vidéo (Annex B, jeux de paramètres, image clé, pts) vont à l'app au lieu de VLC. KyberKit les décode avec VideoToolbox (matériel exigé, mode temps réel, sortie dans les formats compressés sans perte des puces Apple, lus sans copie par Metal) et les dessine avec Metal (conversion YCbCr → RGB selon la matrice du flux). Mesuré hors ligne sur M4 Max en 2560 × 1440 (2026-10-20) : 2,0 ms de décodage en 4:2:0, 2,7 ms en 4:4:4. La session n'utilise pas VLC : l'AV1 n'est proposé qu'aux Mac qui le décodent en matériel (puces M3 et suivantes). Code sans AppKit (décodeur, rendu, capacités, sortie du son) : repris tel quel sur iOS/tvOS.
- **Son par l'app** : le même correctif fait passer les paquets Opus à l'app (`kyclient_audio_session_config_set_packet_sink`). Le moteur de son du cœur les décode (libopus multistream, masquage des pertes) dans un tampon adaptatif d'une vingtaine de ms (VLC : 50 ms fixes, plus le sien) ; Core Audio (apps Apple, demandes de 5 ms à la carte son) ou WASAPI (Windows) tirent les échantillons. Côté serveur, `server/kyber-patches/0004` : paquets Opus de 10 ms en `lowdelay` (la capture WASAPI, elle, reste à la période de Windows). Son et image partent chacun dès qu'ils sont prêts ; l'écart est affiché dans la barre de session. Liste complète des changements : [docs/kyber-changes.md](docs/kyber-changes.md).
- **Souris, presse-papiers, débit, latence** : souris Auto, Bureau ou Jeu (relative, GCMouse), réglable dans la barre de session et par ⌃⌥⌘M ; Auto passe en mode jeu quand Admin voit un jeu en plein écran sur l'ordinateur (pas un navigateur ni un lecteur vidéo), pas au simple masquage du pointeur que Windows fait sans cesse sans souris branchée ; presse-papiers texte partagé dans les deux sens (`apps/macos/kyber-patches/0002` sur libkynput) ; débit des profils proportionné aux pixels par seconde de la session ; latence de bout en bout (capture → affichage) mesurée avec les horodatages et le recalage d'horloge de Kyber, dans la barre et sur l'accueil.
- **Reprise après une perte** : sous rafraîchissement progressif, NVENC n'envoie jamais d'image clé, et VideoToolbox fige l'image après une perte que la FEC ne répare pas. L'app demande donc une image clé (`POST /force_idr`, `server/kyber-patches/0005` sur kycontroller, dans la surcouche), et relance le flux sans réponse en 1,5 s.
- **Définition** : « Comme cet écran » suit l'écran du Mac au pixel près (5K, 6K), jusqu'à 7680 × 4320 (limite d'Admin et de l'écran virtuel), 4096 de large au plus en H.264 (limite de NVENC). Option « Au plus 4K » pour alléger l'encodage, le décodage et le débit.
- **Capacités du client** : au lancement, l'app vérifie les décodeurs matériels (H.264, HEVC, AV1) et décode pour de bon une image HEVC 4:4:4 en exigeant le matériel. Les profils s'y ramènent (sans 4:4:4 matériel : 4:2:0 avec plus de débit ; sans HEVC : H.264), la carte « Ce Mac » des réglages l'affiche, avec la définition et la fréquence de l'écran (variable ou non).

### Sortie audio virtuelle (session de stream)
- **Pourquoi** : sans elle, le son sort aussi des haut-parleurs de l'ordinateur, au format réglé dans Windows, et disparaît si la sortie était l'HDMI d'un écran éteint par l'écran virtuel.
- **Pilote** : Steam Streaming Speakers (Valve, signé par Microsoft, stéréo à 7.1), installé par l'installateur depuis le dossier de Steam s'il est présent (comme Sunshine et Apollo). Aucun pilote libre n'est signé (Virtual-Audio-Driver exige le mode test) ; plan B : notre propre pilote signé par Microsoft (certificat EV + Partner Center au nom des Lignes Claires).
- **Session** : `prepare` reçoit `audio_channels` (2, 6, 8 ; 0 = son sur l'ordinateur). Le son bascule vers les haut-parleurs virtuels réglés à ce format (`IPolicyConfig`, comme le panneau Son) avant l'écran virtuel ; à la fin, la sortie d'origine revient après les écrans (elle peut revenir avec eux). Même filets de sécurité que l'écran virtuel (état sur disque, 20 s sans nouvelles). Page « Son » d'Admin : déclenchement et nombre de canaux.

### Pointeur de souris
- **Constat** : Kyber n'incruste pas le curseur dans l'image ; le client le dessine d'après les annonces de l'ordinateur et bascule en souris relative dès que Windows le dit masqué, sans délai. D'où un curseur qui clignote ou disparaît.
- **Correctifs** : txproto n'annonce un masquage qu'après 250 ms (`server/kyber-patches/0002`) ; Admin coupe « Masquer le pointeur pendant la frappe » le temps de la session ; les apps gardent le curseur visible en souris Bureau et réservent la souris relative au mode Jeu (voir « Souris » plus haut).
- **Reste possible** : Windows sans souris physique masque son curseur en permanence ; à surveiller sur un ordinateur sans souris.

### Correctifs de Kyber
- `server/kyber-patches/build.sh` recompile kyavserver et txproto pour Windows depuis macOS (voir docs/build-notes.md) et assemble `third_party/payload/kyber-overlay/`, posée par l'installateur par-dessus Kyber 0.29. La chaîne kyavserver (txproto, Lua, SPIRV-Cross, runtime MinGW) est compilée en UCRT ; aucun autre binaire de Kyber n'en dépend.
